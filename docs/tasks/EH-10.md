# EH-10 feature — Package the production web and worker roles

> Tracking contract, not an implementation assignment. Execute the small stories in [`docs/stories/EH-10.md`](../stories/EH-10.md).

## Purpose / outcome

Produce one reproducible, non-root EchoHoard image that runs separate web and worker roles safely without embedding deployment-specific secrets or data.

## Primary user story

As an operator, I want one reproducible artifact for separate web and worker roles, so that deployment and rollback stay simple and inspectable.

## Start state

Application behavior passes repository tests, but no production image, hardened runtime, generic Compose, SBOM, or container recovery proof exists.

## End state

One pinned non-root image runs both roles independently and passes the synthetic container critical path plus worker-interruption recovery.

## Repository

`/home/matthijs/projects/echohoard`

## Context / constraints

- One codebase/image; Compose may start `web` and `worker` roles separately.
- Python/`wa-crypt-tools` is local to the worker role, not a network service.
- The public repository may include generic examples only.

## Scope

- Create a multi-stage pinned container build with Node, application artifacts, and a pinned/verified Python decryption dependency.
- Run as non-root with explicit writable data/work paths and read-only secret-file mounts.
- Add role commands, graceful shutdown, health/readiness checks, resource/time bounds, and migration procedure.
- Add a generic Compose example using external PostgreSQL and placeholder secret files.
- Generate an SBOM/attribution record sufficient for redistributed dependencies and document upgrade/rollback steps.
- Add container-level CI smoke tests for both roles and decryption adapter availability without real keys/data.

## Acceptance criteria

- One immutable image digest starts web and worker roles with least required filesystem access.
- Neither image history nor environment/config examples contain secrets or private host details.
- Web stays available when the worker is stopped or processing fails.
- Worker shutdown does not corrupt a claimed job and stale work is recoverable.
- The image build pins and records upstream artifacts and licenses.

## Verification

- Build the image twice from the same inputs and compare the documented reproducibility expectations/digests.
- Scan layers, SBOM, logs, environment examples, and process lists for sentinel secrets.
- Run generic Compose with PostgreSQL, execute migrations, import a synthetic snapshot, browse/search it, and call every MCP tool.
- Stop/kill the worker during each intake phase and verify recovery behavior.

## Out of scope

Private Unraid paths, Vault/AppRole creation, Authentik client creation, Caddy routes, Komodo deployment, Borg jobs, or live Saphira config.
