# EH-03 — Preserve and decrypt snapshot batches

## Goal

Turn one stable inbox delivery into an immutable, checksummed EchoHoard snapshot and a validated disposable SQLite database without exposing the key or mutating the source.

## Repository

`/home/matthijs/projects/echohoard`

## Context / constraints

- Android sync is external; EchoHoard owns everything after files appear under `/data/inbox/<delivery-id>`.
- Use pinned `wa-crypt-tools` as a subprocess, not a Python service or reimplementation.
- The decryption key comes from a configured secret file and must not appear in argv, logs, manifests, or PostgreSQL.

## Work to do

- Implement polling, quiet-period stability checks, atomic claiming, hashing, snapshot-directory creation, manifest creation, and duplicate-hash handling.
- Implement ImportJob/Snapshot transitions and stale-lease recovery for one worker replica.
- Build a bounded subprocess adapter that supplies the key without exposing it in process listings and validates the decrypted output as read-only SQLite.
- Ensure per-job work cleanup on success and handled failure while preserving immutable inputs.
- Classify/redact corrupt-source, invalid-key, unsupported-format, timeout, I/O, and internal errors.
- Add synthetic encrypted/decrypted test fixtures or a test double where licensing prevents committing an encrypted fixture.

## Acceptance criteria

- An unchanged source hash resolves to one logical snapshot and one completed decryption effect.
- Source bytes and timestamps remain unchanged after every outcome.
- A growing/changing batch is never claimed until quiet.
- The manifest contains only allowlisted non-secret metadata and verified SHA-256 values.
- Plaintext work is absent after success and expected failure.
- A failed job remains actionable and retryable without duplicate state.

## Verification

- Unit-test settling, claiming, state transitions, redaction, timeout, and cleanup.
- Functional-test two worker contenders, a duplicate source, crash/stale lease, invalid key, corrupted input, and successful SQLite validation.
- Inspect process arguments and captured logs during decryption for the sentinel test key.
- Hash the source before and after the run.

## Out of scope

Parsing WhatsApp tables, importing messages/media, phone synchronization, or production secrets.
