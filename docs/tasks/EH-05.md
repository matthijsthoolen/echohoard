# EH-05 — Import rich messages and content-addressed media

## Goal

Preserve and safely expose the common non-text WhatsApp message types and copy available referenced attachments into EchoHoard-owned content-addressed storage.

## Repository

`/home/matthijs/projects/echohoard`

## Context / constraints

- Required types are reactions, images, video, voice/audio, documents, locations, contacts, stickers, and source/system events, plus metadata for replies/edits from EH-04.
- Media may be absent or arrive in a later delivery.
- EchoHoard owns its bytes; Immich correlation and physical cross-product deduplication are out of scope.
- Source paths and MIME values are hostile.

## Work to do

- Extend versioned adapters and synthetic fixtures for required types and unknown codes.
- Resolve source media through indexed, normalized relative paths and safe filename fallback without accepting arbitrary traversal.
- Stream SHA-256 calculation and atomic CAS writes; deduplicate identical bytes within EchoHoard.
- Record available/missing/unsafe state, original metadata, dimensions/duration when cheaply available, and message links.
- Add bounded media serving by attachment ID with safe inline MIME allowlist, range support for audio/video, and forced downloads for active/ambiguous content.
- Add later-batch reconciliation for previously missing media.

## Acceptance criteria

- Common rich types survive import with source provenance and correct message relationships.
- Two references to identical bytes store one CAS object without losing either reference.
- Missing media does not fail message import and can become available after a later batch.
- Path traversal, symlink escape, MIME spoofing, HTML, and SVG cannot cause arbitrary file access or active inline execution.
- No code reads Immich's database or storage as an archive dependency.

## Verification

- Unit-test path normalization, hash addressing, MIME policy, range calculations, and reconciliation.
- Functional-test atomic CAS writes, duplicate bytes, missing/later media, interrupted writes, unsafe filenames, symlinks, and archive isolation.
- Browser/API-test image display, audio/video seek, safe document download, missing placeholder, and blocked active content.

## Out of scope

Immich matching, thumbnails beyond browser-safe baseline behavior, OCR, transcription, export, and restore-to-phone.

## Blocked by

EH-04.
