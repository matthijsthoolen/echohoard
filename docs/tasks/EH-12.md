# EH-12 — Accept real data, scale, security, and Hermes traversal

## Goal

Prove EchoHoard works end to end with the owner's real multi-million-message archive, nightly operating window, authenticated UI, restored data, and fresh Hermes/Saphira MCP calls.

## Repository

- `/home/matthijs/projects/echohoard` for reproducible fixes and non-personal benchmark evidence.
- `/home/matthijs/projects/unraided-treasures` for private acceptance records and deployment-only changes.

## Context / constraints

- This is attended acceptance. Real backups, keys, messages, media, identities, queries, screenshots, and raw logs never enter Git, public CI, Plane bodies, or model-visible output.
- Start with copies/immutable snapshots; never modify the only source.
- Passing tests, a successful Procedure, healthy containers, or matching hashes alone do not satisfy end-to-end acceptance.

## Work to do

- Import at least two real snapshots with overlap plus available/missing media, including one reimport and a changed order where safely reproducible.
- Compare aggregate counts/types and selected private samples against Whapa or another independent read-only oracle.
- Measure full/incremental import, search, conversation load, statistics, and media-serving behavior at actual scale; tune only measured bottlenecks inside established boundaries.
- Exercise hostile real/synthetic content, unknown types, damaged text, missing media, invalid auth, and archive-isolation probes.
- Verify Authentik UI use from the intended client path.
- Register/allowlist MCP tools only after endpoint tests pass; make fresh Hermes/Saphira calls for discovery, hostile synthetic content, archive status, search, conversation retrieval, and media metadata.
- Trigger the scheduled backup, restore the accepted recovery unit in isolation, and repeat a known search/media check against the restore.
- Record sanitized final counters, timings, versions/digests, snapshot hashes, failure counts, and unresolved gaps.

## Acceptance criteria

- More than two million real messages import without duplicate logical records or silent loss in the independently checked sample/count set.
- Reimport is idempotent and the tested snapshot ordering converges.
- Full import completes within six hours; representative warm searches and first-page conversation loads meet p95 two seconds on recorded production hardware.
- Common content is browsable/playable; missing and unknown content is explicit and counted.
- Authentik and MCP negative tests deny access without leaking archive metadata.
- Fresh Hermes/Saphira invocations return bounded, provenance-bearing, untrusted evidence from EchoHoard; discovery/configuration alone is insufficient.
- The isolated restored archive passes the same known search and sample-media hash/playback check.
- No key, token, message body, personal identifier, private hostname, or real media is present in committed evidence.

## Verification

- Use the versioned acceptance checklist and store sensitive raw output only in approved private ephemeral locations.
- Reconcile database/import counters with manifests and the independent parser.
- Capture latency distributions, import durations, resource peaks, versions, image digests, and fresh uptimes in sanitized form.
- Run automated negative/security suites against the deployed endpoints and manually confirm representative UI/media behavior.
- Re-run the acceptance query against the isolated restore and compare stable IDs/counts/hashes.

## Out of scope

Fixing unrelated historical source corruption, inferring deletion from absence, AI memory extraction, semantic search, live WhatsApp, or relaxing a boundary merely to make acceptance pass.
