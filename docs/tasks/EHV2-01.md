# EHV2-01 feature — Invisible multi-account live ingestion

> V2 tracking contract. Execute [`docs/stories/EHV2-01.md`](../stories/EHV2-01.md); do not implement this parent as one assignment.

## Outcome

Capture new WhatsApp events between nightly backups through isolated pinned `wacli` sidecars while EchoHoard remains the only user-facing application and archive authority.

## Start state

EH-13 supplies owned accounts and observations, but live linked-device capture and account administration do not exist.

## End state

Each enabled owned account can be paired and monitored from EchoHoard settings. Signed bounded events become EchoHoard observations, reconnect safely, retain revoke/delete history, and reconcile with later backups without duplicate messages.

## Scope

Pinned upstream contract, isolated account stores, fixed sidecar command surface, signed event intake, live normalization, backup reconciliation, settings UI, deployment, and multi-account acceptance.

## Acceptance criteria

- No normal user sees or queries a `wacli` store or interface.
- EchoHoard exposes no send/edit/delete/react/read-receipt/presence-management/general-command capability.
- Replay, reconnect, history events, live events, and later backups converge on one logical message with all observations retained.
- Captured content survives later revoke/delete events and receives a visible source-deleted state.
- Account credentials/session stores are isolated, secret, backed up according to an explicit policy, and never enter Git/logs/Plane.

## Verification

Contract and adapter tests, synthetic webhook fixtures, container isolation checks, two-account functional tests, and attended private pairing/live-to-backup acceptance.

## Out of scope

Guaranteed full history, WhatsApp writes, using `wacli` search as EchoHoard search, or direct UI/database coupling.
