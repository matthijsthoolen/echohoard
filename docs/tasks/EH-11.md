# EH-11 — Integrate the private Unraid deployment and recovery

## Goal

Deploy EchoHoard privately on Unraid with external PostgreSQL, Authentik, Vault-rendered secrets, private MCP networking, and a recovery unit that can be restored independently.

## Repository

- `/home/matthijs/projects/echohoard` for released image/deployment contract fixes only.
- `/home/matthijs/projects/unraided-treasures` for private-instance configuration and evidence.

## Context / constraints

- Use repository-supported, least-privilege Vault and Komodo/unraid-ops procedures; do not embed secrets or use raw Docker/SSH administration.
- Web is available only through the private LAN/Tailscale proxy and Authentik. MCP has no host/public port and is reachable only by the approved Saphira network/client.
- EchoHoard uses a dedicated database/login, Vault identity, OIDC client, storage root, and MCP credential.

## Work to do

- Add the private Compose/stack, pinned image digest, storage mounts, external PostgreSQL provisioning, and network boundaries.
- Provision scoped Vault paths/AppRole and render only role-specific DB, decrypt-key, OIDC, and MCP secret files.
- Configure Authentik for the sole admitted user and private Caddy route without public Cloudflare publication.
- Add Hermes network reachability/configuration prerequisites without enabling unverified tools yet.
- Define the recovery unit: consistent PostgreSQL dump, immutable snapshots/manifests, managed media CAS, required configuration, checksums, retention, restore order, and exclusions for disposable work/cache.
- Configure scheduled Borg protection and perform an isolated restore rehearsal with synthetic/private-safe verification.
- Deploy through the approved procedure and verify fresh process uptime, health, Authentik redirect/login boundary, and job readiness.

## Acceptance criteria

- Application roles receive only their required secret files and database privileges.
- The UI is private and authenticated; MCP is internal and token protected.
- Fresh containers run the released digest and expose no raw host/admin surface.
- Scheduled backup covers the complete recovery unit and excludes decrypted work.
- An isolated restore produces a running, searchable archive with a playable sample attachment.
- Repository/deployment checks and live acceptance evidence are reported separately.

## Verification

- Run repository validation, Compose rendering with secret redaction, and named deployment status/probe procedures.
- Test positive/negative Vault isolation, database role isolation, anonymous/wrong-user web access, and invalid MCP credential.
- Record fresh container start times/digests and live endpoints after deploy.
- Verify backup checksums, restore into an isolated destination, run migrations/readiness, search a known fixture, and hash/play the restored attachment.

## Out of scope

Public internet access, Cloudflare publication, multi-user onboarding, production data import acceptance, and autonomous memory writes.
