# EH-06 — Build bounded read services and PostgreSQL search

## Goal

Provide archive-scoped application services for conversation browsing and fast filtered search at multi-million-message scale, independent of web or MCP delivery.

## Repository

`/home/matthijs/projects/echohoard`

## Context / constraints

- PostgreSQL supplies relational queries, full-text search, and `pg_trgm`; no Elasticsearch, vector database, or embeddings.
- Delivery layers may not query Prisma/PostgreSQL directly.
- Every list is cursor-paginated and bounded.

## Work to do

- Implement archive-scoped services for conversations, messages around a cursor, people resolution, media metadata, and timelines.
- Add migration-managed FTS/trigram structures and parameterized search queries.
- Support filters for conversation/person, direction, date range, and media type with deterministic ordering/cursors.
- Create deterministic generated-corpus tooling for five million messages and one million attachment records.
- Define and capture the representative benchmark query set and query plans.

## Acceptance criteria

- Read/search services return only the requested archive and never unbounded results.
- Cursors are stable when older/newer snapshot data is added.
- Search semantics and filters are documented and deterministic.
- Representative warm searches and first-page conversation loads meet p95 two seconds on the recorded production-class benchmark environment.
- Query plans use intended indexes at reference scale and avoid per-row delivery-layer queries.

## Verification

- Unit-test query/filter/cursor parsing and bounds.
- PostgreSQL functional-test every filter combination, cursor direction, special-character query, empty result, cross-archive denial, and concurrent import visibility.
- Generate the reference corpus, run the versioned benchmark suite, and store non-personal timings plus `EXPLAIN` summaries.

## Out of scope

Semantic/vector search, AI summaries, HTTP/UI rendering, MCP mapping, or statistics dashboards.
