# EH-02 feature — Establish archive schema and isolation

> Tracking contract, not an implementation assignment. Execute the small stories in [`docs/stories/EH-02.md`](../stories/EH-02.md).

## Purpose / outcome

Create the normalized PostgreSQL model and archive-scoped persistence seams that every later feature can use without assuming one global user or leaking WhatsApp schema details.

## Primary user story

As the archive owner, I want every stored object to have durable provenance and an explicit archive owner, so that history remains explainable and isolated.

## Start state

The framework has no EchoHoard domain schema, ownership roots, archive constraints, or application persistence ports.

## End state

PostgreSQL migrations and archive-scoped ports cover all core aggregates, with positive relationship and negative cross-archive functional proof.

## Repository

`/home/matthijs/projects/echohoard`

## Context / constraints

- V1 has one real user but must be structurally ready for multiple isolated users.
- Use the ownership, identity, provenance, and dependency rules in `docs/ARCHITECTURE.md`.
- Do not model deferred embeddings, OCR, transcription, AI memory, or live sync.

## Scope

- Define Prisma migrations for User, Archive, Source, Snapshot, Person, Identity, Conversation, ConversationParticipant, Message, MessageRevision, Reaction, Attachment, MessageAttachment, and ImportJob.
- Include archive scope, stable source identifiers, deterministic-fallback metadata, first/last-seen provenance, timestamps, unknown-type metadata, media availability, and job/snapshot lifecycle fields.
- Add database constraints and indexes that prevent cross-archive references and duplicate stable source objects.
- Expose persistence through application ports and archive-scoped services; keep Prisma inside infrastructure.
- Add a synthetic fixture builder for two isolated archives.

## Acceptance criteria

- Migrations apply cleanly to and roll forward on supported PostgreSQL.
- Every archive-owned lookup requires an explicit archive ID.
- Database constraints reject cross-archive parent/child references.
- Exact stable identities can be linked while fuzzy names remain separate.
- No Prisma type escapes the infrastructure boundary.

## Verification

- Run migration and schema-validation commands against a fresh PostgreSQL database.
- Run functional tests for every unique/cross-archive constraint and positive/negative archive access.
- Run the architecture check and inspect the generated migration SQL/index plan.

## Out of scope

WhatsApp SQLite queries, decryption, full-text search, authentication UI, and real data.
