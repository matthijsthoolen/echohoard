# EHV2-03 feature — Hidden, locked, and MCP-private chats

> V2 tracking contract. Execute [`docs/stories/EHV2-03.md`](../stories/EHV2-03.md).

## Outcome

Give the owner independent control over normal UI visibility, locked access, and MCP disclosure.

## Start state

All authorized reads expose every non-deleted conversation in the archive. WhatsApp lock metadata may be preserved as source metadata but does not control EchoHoard.

## End state

Chats can be normal, hidden, or locked; locked access requires recent Authentik step-up. MCP allow/deny is independent and enforced in shared application services. Search, statistics, galleries, counts, suggestions, and direct URLs cannot leak excluded chats.

## Acceptance criteria

- EchoHoard policy is owner-controlled and distinct from source WhatsApp lock observations.
- Locked chats fail closed after unlock expiry or process restart and require no EchoHoard password database.
- MCP-denied chats and derived records are absent from every MCP tool and aggregate.
- Policy changes are audited without logging titles, identities, or content.

## Verification

Policy matrix tests, PostgreSQL isolation tests, browser step-up/expiry tests, and MCP/search/statistics negative tests.

## Out of scope

Multi-user sharing, custom PIN/secret-code authentication, hiding data from the database owner, or changing WhatsApp lock state.
