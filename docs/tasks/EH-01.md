# EH-01 — Bootstrap framework and quality gates

## Goal

Create the smallest production-shaped EchoHoard framework in which subsequent feature runs cannot bypass type, architecture, test, coverage, or build quality accidentally.

## Repository

`/home/matthijs/projects/echohoard`

## Context / constraints

- Public code, no personal data or private deployment values.
- Use TypeScript, boring Next.js/React, Prisma/PostgreSQL, Tailwind, and shadcn/ui where useful.
- The framework must leave distinct web and worker entrypoints in one package/build without implementing product features.
- Resolve and document the repository license before accepting external contributions; recommended default is `GPL-3.0-only` after confirming dependency/distribution obligations.

## Work to do

- Scaffold the application, package manager, frozen lockfile, Node/toolchain pins, strict TypeScript, environment schema, and deterministic developer commands.
- Create the module layout and mechanically enforce the dependency rules in `docs/ARCHITECTURE.md`.
- Configure formatting, zero-warning linting, type checking, Vitest unit coverage, PostgreSQL-backed functional tests, and a focused browser-test harness.
- Enforce global unit thresholds of 80% statements/lines/functions and 70% branches.
- Add a synthetic test-data policy and one minimal test at each configured seam.
- Add pull-request CI for install, format, lint, types, architecture, unit coverage, functional tests, and production build.
- Add contribution, local development, test, and ADR instructions. Keep tooling minimal and explain every quality dependency.

## Acceptance criteria

- A clean clone has one documented aggregate verification command and independently runnable gates.
- CI fails on a forbidden dependency, type error, lint warning, coverage regression, functional test failure, or production build failure.
- Functional tests apply real Prisma migrations to PostgreSQL.
- The empty framework contains no fake production service, real credential, or personal fixture.
- Web and worker composition roots compile while domain/application modules remain framework-independent.

## Verification

- Install with the frozen lockfile.
- Run format check, lint, strict type check, architecture check, unit coverage, PostgreSQL functional suite, browser harness smoke test, and production build.
- Introduce and revert one forbidden import and one coverage drop to prove both gates fail.
- Inspect the built output and CI logs for secrets and host-specific paths.

## Out of scope

Database domain schema, intake, decryption, importer behavior, product UI, MCP, and private deployment.
