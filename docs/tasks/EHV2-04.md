# EHV2-04 feature — Reversible deletion and owner-only live purge

> V2 tracking contract. Execute [`docs/stories/EHV2-04.md`](../stories/EHV2-04.md).

## Outcome

Make every product deletion reversible while reserving irreversible live-data cleanup for a narrow owner-operated CLI.

## Start state

EH-13 provides tombstone fields but no delete/restore workflow or purge utility.

## End state

The owner can soft-delete and restore supported archive entities. Deleted content is excluded consistently. A guarded local CLI can purge selected live normalized data, derived transcripts, and unreferenced EchoHoard CAS bytes without accessing immutable snapshots or backup repositories.

## Acceptance criteria

- UI/API/MCP operations can only soft-delete and restore.
- Soft-deleted data is absent from default/direct/search/statistics/gallery/MCP reads unless an explicit owner trash view is used.
- Purge defaults to dry-run, requires exact selectors and confirmation, is idempotent, and leaves an identifier-only audit record.
- Purge code cannot traverse snapshot or backup roots.

## Verification

Policy tests, PostgreSQL cascade/restore tests, CAS reference tests, CLI dry-run/destructive fixture tests, and path-denial checks.

## Out of scope

Erasing encrypted source snapshots, Borg/other backups, WhatsApp data, or automatic retention policies.

EH-13-08.
