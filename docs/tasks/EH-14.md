# EH-14 feature — Deliver a Saphira-branded failure experience

> Tracking contract, not an implementation assignment. Execute the small stories in [`docs/stories/EH-14.md`](../stories/EH-14.md).

## Purpose / outcome

Turn authentication denials and other browser-visible failures into clear, calm, recognizable EchoHoard experiences while establishing one reusable visual identity for Saphira across products.

## Primary user story

As the owner, I want every EchoHoard failure to explain what happened through the same interface and a recognizable Saphira illustration, so that errors feel intentional and I always have a useful next action.

## Start state

- A denied OIDC callback returns the raw text `access denied`.
- EchoHoard has no shared application-error component, error registry, designed 404 page, or framework-level 500 fallback.
- EchoHoard and GrandRadio contain related blue-dragon artwork, but no canonical Saphira character reference, prompt contract, or reusable generation skill exists.
- A new image-generation run may change Saphira's face, horns, proportions, palette, or rendering style unintentionally.

## End state

- OnzeSkills contains a validated `saphira-brand-images` skill with canonical Saphira reference assets, invariant character guidance, example prompts, negative prompts, and review criteria.
- EchoHoard uses one accessible error-page system for every browser-facing error it owns, with a distinct Saphira composition for each registered error kind and a designed unknown-error fallback.
- The access-denied experience says “You shall not pass!” and explains safely that access was denied without exposing identity, archive, token, or diagnostic details.
- Error pages preserve meaningful status behavior where the framework permits it, render consistently on mobile and desktop, show the current application version, and offer only useful non-looping actions.

## Repositories

- `/home/matthijs/projects/OnzeSkills` — canonical Saphira visual-generation skill and reusable reference pack.
- `/home/matthijs/projects/echohoard` — generated product illustrations, error registry, pages, routing, and tests.

## Context / constraints

- Use the existing GrandRadio and EchoHoard dragons as approved source references, but derive a deliberate canonical character rather than treating either product-specific composition as a complete character sheet.
- Saphira remains a luminous blue/cyan/violet dragon. Product props, pose, mood, and background may vary; identifying anatomy and palette may not drift between images.
- Keep headings, descriptions, error codes, and actions as HTML. Do not bake required text into generated images.
- Error copy is sanitized and does not reveal whether a protected archive, person, conversation, or message exists.
- API and MCP callers continue to receive their bounded machine-readable errors; this feature owns browser-facing presentation.

## Initial browser error catalog

Every browser-facing failure emitted by EchoHoard must resolve through a registered error kind. The initial catalog is finite; a new human-facing failure kind must extend the registry and provide artwork before it ships.

| Kind | HTTP class | Saphira composition | Primary recovery |
|---|---:|---|---|
| Bad request | 400 | Saphira examining a damaged or confusing archive scroll | Correct or restart the request |
| Authentication required | 401 | Saphira beside a closed luminous archive portal | Sign in |
| Access denied | 403 | Saphira firmly guarding the archive threshold: “You shall not pass!” | Sign out or try an approved account |
| Not found | 404 | Saphira searching empty archive shelves with a map or lantern | Return to a known archive destination |
| Request timeout | 408 | Saphira protecting a stalled hourglass or frozen message trail | Retry |
| Conflict | 409 | Saphira separating two colliding duplicate records | Reload and retry safely |
| Rate limited | 429 | Saphira calming an overload of message sparks | Wait and retry |
| Unexpected failure | 500 | Saphira repairing tangled glowing archive machinery | Retry or return to a safe destination |
| Service unavailable | 503 | Saphira maintaining a temporarily closed archive gate | Retry later |
| Unknown fallback | Other/unclassified | Saphira holding a flickering question-mark crystal | Return safely or retry |

These are original compositions. The 403 concept may use the short phrase requested by the owner, but it must not imitate a copyrighted character, film frame, costume, or franchise art style.

## Scope

- Establish the portable Saphira image-generation skill and canonical character pack in OnzeSkills.
- Inventory EchoHoard-owned browser failure paths and map them to a typed central registry.
- Generate, review, optimize, and commit one distinct illustration for every initial registered kind using the canonical references.
- Implement shared responsive error presentation plus Next.js not-found, route-denial, recoverable error, and global-error integration.
- Replace raw browser-facing OIDC callback failures with sanitized designed outcomes while preserving authentication and archive-isolation policy.
- Add focused accessibility, routing, status, sanitization, and fallback tests.

## Acceptance criteria

- **EH14-AC-01:** A fresh agent can generate a recognizably consistent Saphira from the OnzeSkills skill without relying on this planning conversation.
- **EH14-AC-02:** The skill bundles approved canonical references, immutable character traits, adaptable traits, reusable positive/negative prompt recipes, output guidance, and objective review checks.
- **EH14-AC-03:** Every EchoHoard-owned browser failure maps to one registered kind; every initial kind has distinct artwork, and an unknown kind renders the designed fallback rather than raw text or a framework default.
- **EH14-AC-04:** The 403 page uses “You shall not pass!”, describes access denial safely, exposes no OIDC or archive details, and offers a useful non-looping account action.
- **EH14-AC-05:** Error experiences share EchoHoard's design tokens, current-version treatment, responsive layout, semantic headings, keyboard focus, reduced-motion behavior, useful alternative text, and WCAG AA text contrast.
- **EH14-AC-06:** Browser-visible failures are sanitized; machine-facing API/MCP error contracts and authorization policy do not change.

## Verification

- Validate and smoke-test the new OnzeSkills skill in every locally available target harness, including positive and neighboring non-trigger prompts.
- Review canonical and generated assets at full size and thumbnail size against the character invariants and product design system.
- Unit-test registry completeness, fallback selection, copy sanitization, actions, and asset existence.
- Browser-test denied OIDC callback, direct 404, recoverable render failure, global failure, service-unavailable treatment, unknown fallback, keyboard flow, mobile width, 200% zoom, and reduced motion.
- Run the focused formatting, lint, type, design-system, unit, browser, and production-build checks affected by the change.

## Out of scope

- Automatically approving the currently denied Authentik identity or weakening archive admission policy.
- Styling errors generated before a request reaches EchoHoard, including Authentik, Cloudflare, Caddy, browser, network, and Komodo error pages.
- Replacing API/MCP JSON errors with HTML, exposing stack traces, or adding an observability platform.
- A general EchoHoard rebrand, animated mascot system, or generated imagery inside message/archive content.
