# EH-04 feature — Import text history with provenance and convergence

> Tracking contract, not an implementation assignment. Execute the small stories in [`docs/stories/EH-04.md`](../stories/EH-04.md).

## Purpose / outcome

Import the smallest complete WhatsApp history slice—people, identities, direct/group conversations, participants, and text messages—so repeated and reordered snapshots converge without losing provenance or revisions.

## Primary user story

As the archive owner, I want overlapping backups to converge into one traceable text history, so that reimports and later omissions never duplicate or erase evidence.

## Start state

Validated SQLite exists, but no versioned schema adapter, stable message identity contract, normalized mapper, or transactional text importer exists.

## End state

Supported synthetic schemas import transactionally, unsupported schemas fail visibly, and repeated plus permuted snapshots converge without inferred deletion.

## Repository

`/home/matthijs/projects/echohoard`

## Context / constraints

- Only a versioned `WhatsAppAndroidAdapter` may know SQLite tables, columns, JIDs, LIDs, or type codes.
- SQLite row IDs are not durable identifiers.
- Missing data in a later snapshot never deletes archive history or proves deletion.
- Preserve malformed text safely and report damage rather than aborting the entire source silently.

## Scope

- Define the adapter contract and schema-fingerprint/selection mechanism.
- Implement synthetic current and relevant legacy schema fixtures for identity, chats, participants, text, replies, and edits.
- Map stable source identifiers and implement a versioned deterministic fallback with collision detection.
- Implement transactional/batched normalization, revision preservation, first/last-seen updates, and snapshot finalization.
- Preserve unknown message codes as inert unsupported records.
- Add idempotency and all-permutation convergence tests for representative snapshots A/B/C.

## Acceptance criteria

- Repeat imports do not change logical counts or identifiers.
- A/B/C import order converges except for explicit chronology fields.
- Later absence leaves prior messages visible.
- Text edits create/reuse deterministic revisions rather than overwriting history.
- Unknown types and damaged text remain traceable and visible as unsupported/damaged data.
- Adapter code returns normalized records and never writes PostgreSQL directly.

## Verification

- Run unit tests for identifiers, fallback collisions, revisions, malformed text, and adapter selection.
- Run PostgreSQL functional tests for repeated imports, every A/B/C permutation, failure before finalization, and retry.
- Compare private sample counts against a human-run Whapa report without committing either dataset or content.

## Out of scope

Media bytes, rich message rendering, search, statistics, UI, and MCP.
