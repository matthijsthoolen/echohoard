# EH-13 feature — Multi-source provenance and reversible imports

> V1.1 tracking contract, not an implementation assignment. Execute the leaves in [`docs/stories/EH-13.md`](../stories/EH-13.md).

## Purpose / outcome

Establish the data contracts required to load several owned WhatsApp accounts and overlapping backup/live sources before real data is accepted, without losing the ability to explain or exclude any import.

## Primary user story

As the archive owner, I want every normalized item to retain all source observations and its receiving account, so that overlapping imports deduplicate safely and a corrupt import can be excluded without damaging valid history.

## Start state

V1 has Source, Snapshot, ImportJob, stable normalized identifiers, and first/last-seen fields, but no owned-account root, source-conversation layer, complete observation ledger, or deterministic import exclusion/rematerialization.

## End state

Owned accounts and immutable source observations drive normalized state. Source conversations can later be grouped without losing identity. Excluding and re-enabling an import deterministically rematerializes the same eligible archive, while source-deletion events become append-preserving tombstones.

## Scope

- Record the schema and reconciliation decision in an ADR.
- Add owned-account, source-conversation, unified-conversation foundation, and typed observation persistence.
- Bind every imported observation to account, source, snapshot, and import job.
- Add reversible import eligibility plus deterministic rematerialization.
- Represent WhatsApp delete/revoke observations without erasing captured content.
- Prove migration, replay, overlap, reorder, exclusion, and multi-account isolation with synthetic data.

## Acceptance criteria

- The same source message observed live and in one or more backups produces one logical message and multiple immutable observations.
- Identical-looking chats on two owned accounts remain separate source conversations until explicitly grouped.
- Every visible message, conversation, revision, reaction, and attachment reference can enumerate its contributing imports.
- Excluding a corrupt import removes only conclusions unsupported by remaining eligible observations; re-enabling it restores the prior deterministic state.
- Revoke/delete observations preserve previously captured content and source metadata.
- Existing V1 behavior migrates without a global single-account shortcut or cross-archive leak.

## Verification

Run schema/migration checks, architecture checks, focused unit tests, PostgreSQL functional permutations, and a generated scale rematerialization benchmark. EH-12 real-data acceptance must not begin until EH-13-08 is Done.

## Out of scope

Merge UI, live sidecar deployment, privacy UI, delete/restore UI, purge execution, media recovery, transcription, and real-data migration.
