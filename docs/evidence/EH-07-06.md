# EH-07-06 viewer verification

This record covers the repository-level viewer seam for accessibility,
responsive layout, authorization boundaries, and the bounded timeline model.
It intentionally does not claim live Authentik acceptance: that requires a
private deployment session and is owned by the later deployment/attended
acceptance stories.

## Automated checks

Run:

```text
pnpm test:viewer
```

The harness builds and starts the production web role, audits the server HTML
at desktop (1440x900) and mobile (390x844) target widths, checks landmarks,
heading order, labels, skip navigation, and positive tabindex, and verifies
anonymous archive routes deny access. With
`ECHOHOARD_VIEWER_SESSION_COOKIE` set to a private test session, it additionally
checks bounded conversation browsing, both history directions, and bounded
search pages.

The harness uses Node fetch and does not require a browser binary. It is a
deterministic critical-path seam; keyboard inspection remains a manual step.

## Keyboard smoke

The expected order is skip link, wordmark, primary navigation, search controls,
conversation links, timeline controls, and the focusable message-history
viewport. Focus indicators use `:focus-visible`; mobile navigation remains
keyboard reachable after the desktop rail is hidden.

## 150,000-message profile

Run:

```text
pnpm profile:viewer-memory
```

Recorded deterministic result:

```json
{
  "messagesProfiled": 150000,
  "pageSize": 50,
  "retainedWindow": 300,
  "peakRetainedMessages": 300,
  "result": "bounded"
}
```

This is a browser-model profile of the client retention policy, not a browser
heap measurement. Live browser memory profiling remains part of attended
deployment acceptance because this public repository has no browser automation
runtime or real authenticated archive.

- Timeline delivery now preserves validated attachment and metadata fields so

- The message-history viewport is keyboard focusable for desktop and mobile
