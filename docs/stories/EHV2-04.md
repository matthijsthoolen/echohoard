# EHV2-04 stories — Reversible deletion and owner-only live purge

Owning feature: `docs/tasks/EHV2-04.md`. Immutable snapshots and external backups are never purge targets.

## EHV2-04-01 — Implement audited soft-delete and restore commands

- **Goal:** Add reversible owner deletion for conversations, messages, and attachments through one domain policy.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** EH-13 provides tombstone fields. Source-deleted and owner-deleted are independent. Define cascade presentation behavior without physically cascading rows.
- **Work to do:** Add soft-delete/restore application commands, reason/audit/version fields, and persistence; define conversation deletion as hiding descendants through effective policy while retaining their individual state.
- **Acceptance criteria:** Commands are idempotent/archive-scoped/audited; restore returns prior eligible content; no ORM delete is invoked; source observations and immutable inputs remain unchanged; concurrency conflicts are explicit.
- **Verification:** Unit tests and PostgreSQL functional tests for hierarchy, replay, restore, overlap, source deletion, and isolation.
- **Out of scope:** UI, query filtering, physical purge, or retention schedules.
- **Blocked by:** EH-13-08.
- **Priority:** High.
- **Model class:** Medium.

## EHV2-04-02 — Exclude soft-deleted records from every normal read

- **Goal:** Enforce deletion consistently across web, search, statistics, media, health, and MCP application services.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Filtering occurs in shared application/persistence contracts, not independently in UI/MCP handlers. Direct identifiers must not leak deleted existence.
- **Work to do:** Add effective-deletion filters and explicit owner-trash read mode; update aggregates/index behavior and cursor stability; define restoration reindexing.
- **Acceptance criteria:** Normal/direct/search/gallery/statistics/MCP reads exclude deleted data and derived counts; trash reads require owner purpose; restore returns content/searchability; pagination has no skip/duplicate around state changes.
- **Verification:** PostgreSQL read matrix and MCP/browser contract tests with mixed delete/privacy/unified states.
- **Out of scope:** Mutation UI, physical purge, or private deployment.
- **Blocked by:** EHV2-04-01, EHV2-03-05.
- **Priority:** High.
- **Model class:** Medium.

## EHV2-04-03 — Add trash, delete, and restore UX

- **Goal:** Let the owner soft-delete and restore supported content with clear non-destructive language.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** UI never offers hard delete. Actions must clarify effective conversation cascade and distinguish WhatsApp-deleted from owner-deleted.
- **Work to do:** Add actions/confirmations, trash views and filters, restore flows, audit summary, conflict/error recovery, and accessible responsive behavior.
- **Acceptance criteria:** Delete disappears from normal views without removing source; trash shows the correct entity/reason/time; restore works; no hard-delete language/control exists; protected-chat authorization remains required.
- **Verification:** Component and browser tests for message/conversation/media deletion, restore, locked content, conflicts, and mobile/keyboard use.
- **Out of scope:** Purge CLI, bulk retention policy, or source deletion.
- **Blocked by:** EHV2-04-01, EHV2-04-02.
- **Priority:** Medium.
- **Model class:** Medium.

## EHV2-04-04 — Build the guarded owner-only live purge CLI

- **Goal:** Irreversibly purge exact soft-deleted live rows, derived transcripts, and newly unreferenced EchoHoard CAS objects only when invoked locally by the owner.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Default is dry-run. Exact archive and entity selectors, owner confirmation, minimum tombstone age, transaction plan, CAS reference recheck, and protected runtime identity are mandatory. Snapshot/inbox/backup roots are structurally inaccessible.
- **Work to do:** Implement plan/apply CLI with manifest digest and typed selectors; purge in safe referential order; retain identifier-only audit receipt; add failure recovery and orphan-CAS handling.
- **Acceptance criteria:** No apply without matching dry-run digest and explicit confirmation; non-soft-deleted/shared/CAS-referenced data is refused; retries are idempotent; path escape and snapshot/backup access are impossible; stdout/stderr contain no content.
- **Verification:** Disposable PostgreSQL/filesystem functional suite covering dry-run, stale plan, shared media, injected failures, retry, wrong owner/archive, and forbidden roots.
- **Out of scope:** Production execution, encrypted snapshots, external backups, WhatsApp deletion, or scheduled retention.
- **Blocked by:** EHV2-04-01, EHV2-06-06.
- **Priority:** Medium.
- **Model class:** Complex — irreversible referential and CAS cleanup is one deliberately isolated risk boundary.

## EHV2-04-05 — Package and privately verify purge access boundaries

- **Goal:** Ensure only the owner can invoke the exact purge CLI in the live environment and normal web/worker/MCP roles cannot.
- **Repository:** `/home/matthijs/projects/unraided-treasures`
- **Context / constraints:** Use an owner-attended, non-networked one-shot Procedure or direct protected host command explicitly approved for this utility; never expose generic terminal authority through the application.
- **Work to do:** Add fixed runtime/secret/mount contract; grant no scheduled or application execution path; run dry-run and disposable-data apply; verify denial from web, worker, MCP, and automation identities.
- **Acceptance criteria:** Only owner-attended path executes; live target excludes snapshot/backup mounts; disposable soft-deleted fixture purges and shared data survives; denial tests pass; no secret/content appears in evidence.
- **Verification:** Approved deployment/runtime checks and an attended disposable purge rehearsal with sanitized counters/digests.
- **Out of scope:** Purging real archive data, granting general shell access, or modifying backup retention.
- **Blocked by:** EHV2-04-02, EHV2-04-04.
- **Priority:** Medium.
- **Model class:** Complex — live irreversible-authority acceptance must remain attended and isolated.
