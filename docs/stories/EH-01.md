# EH-01 stories — Framework and quality gates

Owning feature: `docs/tasks/EH-01.md`. Only the leaf stories below are executable assignments.

## EH-01-01 — Pin the toolchain and compile empty web/worker shells

- **Goal:** Create a deterministic TypeScript/Next.js workspace with compiling web and worker entrypoints and no product behavior.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Use one package/build, a frozen lockfile, strict TypeScript, environment-schema validation, and public synthetic defaults only.
- **Work to do:** Pin Node and the package manager; scaffold the Next.js web composition root and worker composition root; add deterministic install, type-check, build, and start commands.
- **Acceptance criteria:** A clean checkout installs from the frozen lockfile; strict type-check and production build compile both roles; no credentials, private paths, fake services, or product features exist.
- **Verification:** Run frozen install, strict type-check, production build, and both role smoke starts with synthetic configuration.
- **Out of scope:** Architecture enforcement, test harnesses, CI, database schema, intake, UI features, and deployment.
- **Blocked by:** None.
- **Priority:** High.
- **Model class:** Simple.

## EH-01-02 — Enforce module dependency boundaries

- **Goal:** Make the dependency directions in `docs/ARCHITECTURE.md` mechanically enforceable.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Domain must remain framework-independent; delivery and workers call application services; infrastructure and WhatsApp adapters implement ports.
- **Work to do:** Create the documented module directories with minimal public entrypoints; configure one architecture-check mechanism; add positive and deliberately failing fixtures for representative allowed/forbidden imports.
- **Acceptance criteria:** The documented module layout compiles; forbidden imports fail the architecture command with actionable output; allowed dependency directions pass without exemptions.
- **Verification:** Run the architecture check, then introduce and revert one forbidden import to prove failure.
- **Out of scope:** Domain entities, Prisma schema, application use cases, product UI, and additional architecture tooling.
- **Blocked by:** EH-01-01.
- **Priority:** High.
- **Model class:** Simple.

## EH-01-03 — Enforce unit-test coverage and lint quality

- **Goal:** Establish fast mandatory unit-quality gates before business code is added.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** CI accepts no lint warnings; global minimums are 80% statements/lines/functions and 70% branches; generated/declarative exclusions must be explicit.
- **Work to do:** Configure formatting, zero-warning linting, Vitest, coverage thresholds, and one synthetic unit seam; expose independent and aggregate local commands.
- **Acceptance criteria:** Format, lint, and unit commands pass on the scaffold; lowering actual coverage below any threshold fails; business modules cannot be excluded to manufacture coverage.
- **Verification:** Run all three gates and introduce/revert one lint warning and one coverage drop.
- **Out of scope:** PostgreSQL tests, browser tests, CI jobs, and product tests.
- **Blocked by:** EH-01-01.
- **Priority:** High.
- **Model class:** Simple.

## EH-01-04 — Add the PostgreSQL functional-test harness

- **Goal:** Provide a repeatable functional-test environment that applies real Prisma migrations to PostgreSQL.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Do not substitute SQLite or an in-memory database; fixtures must be synthetic; the harness must cleanly isolate test runs.
- **Work to do:** Configure Prisma's empty initial migration path; provide a disposable PostgreSQL test service and lifecycle commands; add one migration-backed functional smoke test.
- **Acceptance criteria:** A fresh database is migrated by the same mechanism production will use; the smoke test proves database connectivity and cleanup; repeated runs do not depend on leftover state.
- **Verification:** Start the disposable database, apply migrations, run the functional suite twice, and destroy the test state.
- **Out of scope:** EchoHoard domain schema, archive constraints, import queries, browser tests, and private CI wiring.
- **Blocked by:** EH-01-01.
- **Priority:** High.
- **Model class:** Medium.

## EH-01-05 — Add a focused browser-test harness

- **Goal:** Establish a browser smoke-test seam without building product screens.

## EH-01-06 — Wire pull-request CI and contributor contracts

- **Goal:** Make every established quality gate mandatory and understandable for future contributors and agents.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** CI must use frozen dependencies and synthetic data; reducing coverage or architecture rules requires an ADR and maintainer approval.
- **Work to do:** Add pull-request jobs for install, format, lint, types, architecture, unit coverage, PostgreSQL functional smoke, browser smoke, and production build; document aggregate/local commands and ADR/contribution rules; scan build/CI output for private values.
- **Acceptance criteria:** Every gate is represented and fails the pull request when broken; local documentation maps exactly to CI commands; CI contains no secrets, personal fixtures, or host-specific paths.
- **Verification:** Validate workflow syntax, run the aggregate command locally, and inspect a successful plus intentionally failing representative CI run.
- **Out of scope:** Container builds, product functionality, private deployment, and choosing the public license beyond recording the existing open decision.
- **Blocked by:** EH-01-02, EH-01-03, EH-01-04, EH-01-05.
- **Priority:** High.
- **Model class:** Medium.
