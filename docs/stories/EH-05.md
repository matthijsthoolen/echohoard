# EH-05 stories — Rich messages and content-addressed media

Owning feature: docs/tasks/EH-05.md. Only the leaf stories below are executable assignments.

## EH-05-01 — Map common rich message types

- **Goal:** Extend normalized adapter output for reactions, images, video, voice/audio, documents, locations, contacts, stickers, and source/system events.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Follow the EH-04 adapter contract and stable identities; unknown codes remain inert unsupported records; media bytes are handled separately.
- **Work to do:** Extend synthetic fixtures for common rich types; implement normalized mapping and relationships; add current/legacy adapter tests.
- **Acceptance criteria:** Every required type maps with source identifiers, timestamp, safe metadata, and message relationships; unknown codes remain traceable; adapter emits no active content or PostgreSQL writes.
- **Verification:** Run adapter tests across supported schema fixtures and hostile metadata cases.
- **Out of scope:** Resolving/copying media bytes, media serving, UI rendering, OCR, and transcription.
- **Blocked by:** EH-04-07.
- **Priority:** High.
- **Model class:** Simple.

## EH-05-02 — Resolve referenced media paths safely

- **Goal:** Resolve adapter-provided media observations to files without traversal, arbitrary paths, or symlink escape.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Source paths and filenames are hostile; resolution starts from indexed normalized relative paths with a bounded filename fallback.
- **Work to do:** Implement path normalization and indexed lookup; implement safe fallback matching; reject traversal, absolute paths, and links escaping the delivery root.
- **Acceptance criteria:** Valid fixture paths resolve deterministically; traversal/absolute/symlink escapes never return bytes; ambiguous fallback produces an explicit unresolved state.
- **Verification:** Run unit/filesystem tests for normal, Unicode, duplicate-name, traversal, symlink, and ambiguous cases.
- **Out of scope:** Hashing/copying bytes, database updates, HTTP serving, and Immich.
- **Blocked by:** EH-04-07.
- **Priority:** High.
- **Model class:** Medium.

## EH-05-03 — Store media bytes atomically in the SHA-256 CAS

- **Goal:** Stream available attachment bytes into one EchoHoard-owned content-addressed object per hash.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** CAS path is /data/media/sha256/<prefix>/<sha256>; source bytes remain unchanged; partial writes cannot become visible.
- **Work to do:** Implement streaming SHA-256 and bounded copy; implement temp-file plus atomic publish; deduplicate concurrent/duplicate identical bytes.
- **Acceptance criteria:** Identical bytes produce one CAS object and stable hash; interrupted writes leave no accepted partial object; source files are never modified; hash/path mismatches fail closed.
- **Verification:** Run filesystem functional tests for duplicate/concurrent bytes, interruption, retry, mismatch, and large streaming input.
- **Out of scope:** Message links, missing-media state, HTTP serving, thumbnails, and Immich correlation.
- **Blocked by:** EH-05-02.
- **Priority:** High.
- **Model class:** Medium.

## EH-05-04 — Persist media availability and reconcile later arrivals

- **Goal:** Link rich messages to available/missing/unsafe attachments and make missing media recoverable from later deliveries.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Missing media does not fail message import; multiple references may share one CAS object; absence never deletes an available object.
- **Work to do:** Persist attachment/message links and availability transitions; implement later-batch reconciliation by stable observation; add idempotent PostgreSQL tests.
- **Acceptance criteria:** Missing references import successfully; later bytes transition the existing logical attachment to available; duplicate bytes retain all message links; unsafe/unresolved state remains explicit.
- **Verification:** Run PostgreSQL/filesystem functional tests for missing, later-arriving, duplicate, repeated and cross-archive cases.
- **Out of scope:** HTTP serving, UI rendering, external Immich matching, and deletion.
- **Blocked by:** EH-05-01, EH-05-03.
- **Priority:** High.
- **Model class:** Medium.

## EH-05-05 — Serve media with bounded safe MIME and range policy

- **Goal:** Deliver attachments by archive-scoped ID with safe inline/download behavior and audio/video range support.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Never accept a filesystem path from clients; raster image/audio/video use a small allowlist; HTML, SVG, executable, or ambiguous data is forced inert download.
- **Work to do:** Implement authorized attachment lookup and streaming; implement MIME/nosniff/content-disposition policy; implement validated byte ranges for audio/video.
- **Acceptance criteria:** Safe media streams by ID and permitted ranges; active/ambiguous content cannot execute inline; invalid ranges/archives/IDs fail without path disclosure; missing media has an explicit response.
- **Verification:** Run route tests for image, audio/video seek, document download, spoofed MIME, HTML/SVG, invalid ranges, and cross-archive access.
- **Out of scope:** Viewer components, transcoding, thumbnails, arbitrary URL fetch, and export.
- **Blocked by:** EH-05-03.
- **Priority:** High.
- **Model class:** Medium.
