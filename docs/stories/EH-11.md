# EH-11 stories — Private Unraid deployment and recovery

Owning feature: `docs/tasks/EH-11.md`. These stories require private infrastructure access and carry `ai-allowed` unless stated otherwise.

## EH-11-01 — Add the private stack, database role, storage, and network boundary

- **Goal:** Define the private EchoHoard web/worker deployment with dedicated PostgreSQL, storage roots, and private networks.
- **Repository:** /home/matthijs/projects/unraided-treasures
- **Context / constraints:** Use the released image digest and approved repository/Komodo patterns; UI is LAN/Tailscale proxy only; MCP has no host/public port; no secrets are embedded.
- **Work to do:** Add the private stack/Compose definition and mounts; provision/document a dedicated database/login boundary through supported mechanisms; validate network exposure and generic secret-file paths.
- **Acceptance criteria:** Rendered configuration uses the pinned digest, external PostgreSQL, dedicated storage, no public MCP/host-admin surface, and no credential values; web/worker roles receive only required mounts/networks.
- **Verification:** Run repository validation and redacted Compose rendering; inspect declared ports/networks/mounts/database grants without deploying.
- **Out of scope:** Vault credentials, Authentik/Caddy, Hermes, deployment execution, backup scheduling, and real data.
- **Blocked by:** EH-10-05.
- **Priority:** High.
- **Model class:** Medium.

## EH-11-02 — Provision least-privilege Vault identities and role-specific secret files

- **Goal:** Deliver only the database, decrypt-key, OIDC, and MCP secrets required by each EchoHoard role.
- **Repository:** /home/matthijs/projects/unraided-treasures
- **Context / constraints:** Use repository-supported Vault Agent/AppRole/bootstrap procedures; never expose SecretIDs, tokens, rendered values, or keys to Git/model/logs; web must not receive the decrypt key.
- **Work to do:** Define scoped Vault paths/policies/identities; configure protected role-specific rendered files; test positive and negative isolation.
- **Acceptance criteria:** Web and worker can read only their named secret files; cross-role/other-workload reads are denied; no secret appears in Compose, Git, command history, or evidence; renewal/restart behavior is documented.
- **Verification:** Use approved redacted status/read procedures and positive/negative policy tests; inspect rendered-file ownership/mode without printing content.
- **Out of scope:** Authentik client, Caddy, stack deployment, secret rotation ceremony, and application changes unrelated to secret-file contract.
- **Blocked by:** EH-11-01.
- **Priority:** High.
- **Model class:** Complex — private Vault policy and secret-delivery boundaries are one irreducible high-impact risk axis.

- **Repository:** /home/matthijs/projects/unraided-treasures

- **Model class:** Medium.

## EH-11-05 — Define and schedule the EchoHoard recovery unit

- **Repository:** /home/matthijs/projects/unraided-treasures
- **Context / constraints:** Exclude disposable plaintext work/cache; use the supported Borg backup workflow; retention and restore order must be explicit.

- **Blocked by:** EH-11-01.
- **Priority:** High.
- **Model class:** Medium.

## EH-11-06 — Deploy privately and rehearse an isolated restore

- **Goal:** Deploy the pinned EchoHoard release and prove its recovery unit restores to a separate searchable, playable instance.
- **Repository:** /home/matthijs/projects/unraided-treasures
- **Context / constraints:** Use named approved procedures, not raw Docker/SSH/admin APIs; distinguish repository checks, procedure success, fresh runtime health, authenticated use, and restore proof.
- **Work to do:** Deploy and record fresh digest/start/health/readiness evidence; verify private web/MCP boundaries; restore the synthetic recovery unit to an isolated destination and test search plus sample-media hash/playback.
- **Acceptance criteria:** Fresh roles run the intended digest and pass readiness; Authentik/MCP negative tests deny access; backup completes; isolated restore starts, migrates, searches a known fixture, and serves the expected attachment hash; disposable plaintext is absent.
- **Verification:** Execute the approved status/log/probe sequence, authenticated route checks, backup checksum checks, and isolated restore checklist.
- **Out of scope:** Production archive import, tool enablement/fresh Hermes calls, public exposure, and unrelated deployment repair.
- **Blocked by:** EH-11-03, EH-11-04, EH-11-05.
- **Priority:** High.
- **Model class:** Complex — coordinated private deployment plus destructive-risk restore isolation is the remaining irreducible integration boundary.
