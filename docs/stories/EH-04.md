# EH-04 stories — Text history import and convergence

Owning feature: `docs/tasks/EH-04.md`. Only the leaf stories below are executable assignments.

## EH-04-01 — Record supported schema fingerprints and adapter contract

- **Goal:** Turn verified WhatsApp schema evidence into a versioned adapter selection and normalized-record contract.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Only the adapter may know tables, columns, type codes, JIDs, or LIDs; Whapa is a read-only oracle, not the runtime model; unknown schemas fail visibly.
- **Work to do:** Inspect synthetic and legally available upstream schema evidence; document current/relevant legacy fingerprints and normalized output fields; define deterministic adapter selection and unsupported-schema behavior.
- **Acceptance criteria:** Every supported fingerprint maps to one named adapter version; ambiguous/unknown fingerprints produce a sanitized unsupported result; the contract records stable identifiers without leaking SQLite concepts into application code.
- **Verification:** Run contract/schema-selection tests against supported, ambiguous, and unknown synthetic schemas; review the decision against docs/ARCHITECTURE.md.
- **Out of scope:** PostgreSQL writes, message import, media, private database content, and guessing unsupported schemas.
- **Blocked by:** EH-03-06.
- **Priority:** High.
- **Model class:** Reasoning — selecting durable schema/identity evidence is the irreducible design decision; later stories must follow this contract.

## EH-04-02 — Build current and legacy synthetic SQLite fixtures

- **Goal:** Provide deterministic, non-personal SQLite fixtures matching every schema family accepted by EH-04-01.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Fixtures cover identities, direct/group chats, participants, text, replies, edits, unknown codes, and malformed text without real content.
- **Work to do:** Add fixture builders for each documented fingerprint; add minimal valid and damaged variants; expose a repeatable fixture-generation/test command.
- **Acceptance criteria:** Generated fixtures select the intended adapter; no fixture contains personal content or licensed database bytes; regeneration is structurally deterministic as documented.
- **Verification:** Generate fixtures twice, compare the documented stable properties, and run adapter-selection tests.
- **Out of scope:** Normalized import, rich media records, production backups, and oracle comparison.
- **Blocked by:** EH-04-01.
- **Priority:** High.
- **Model class:** Simple.

## EH-04-03 — Map identities and conversations to normalized records

- **Goal:** Normalize people, identities, direct/group conversations, and participants without unsafe fuzzy merging.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Follow the adapter contract; preserve JIDs/LIDs/source identifiers as observations; exact verified identifiers may link, similar display names may not.
- **Work to do:** Implement adapter reads/mapping for identities, conversations, and participants; add current/legacy mapping tests; preserve damaged/unknown identity observations safely.
- **Acceptance criteria:** Direct/group membership maps deterministically; exact IDs remain traceable; similar names stay separate; adapter returns normalized records and never writes PostgreSQL.
- **Verification:** Run unit tests against every synthetic schema fixture and architecture checks for the adapter boundary.
- **Out of scope:** Messages, revisions, database upserts, fuzzy search, and UI.
- **Blocked by:** EH-04-01, EH-04-02.
- **Priority:** High.
- **Model class:** Medium.

## EH-04-04 — Derive stable message identities and collision handling

- **Goal:** Produce durable source message keys without depending on SQLite row IDs.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Prefer source message/stanza IDs; fallback fingerprints are versioned, use stable fields, record fallback use, and never silently merge collisions.
- **Work to do:** Implement namespaced stable-key derivation; implement versioned fallback fingerprints; add collision detection and deterministic diagnostics.
- **Acceptance criteria:** Stable source IDs survive row/order changes; identical fallback inputs reproduce the same key; distinct colliding records are rejected/quarantined; no row ID is part of durable identity.
- **Verification:** Run unit/property tests for source-ID, fallback, reordered rows, collision, and version cases.
- **Out of scope:** Message content mapping, PostgreSQL upserts, revisions, and cross-source identity linking.
- **Blocked by:** EH-04-01, EH-04-02.
- **Priority:** High.
- **Model class:** Medium.

## EH-04-05 — Map text, replies, edits, and unsupported messages

- **Goal:** Normalize text history and its relationships while preserving damaged and unknown records as inert evidence.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Use EH-04-04 keys; edits become revisions rather than overwrites; malformed text must not abort the complete source silently.
- **Work to do:** Implement adapter mapping for text, reply references, edits/revisions, direction/timestamps, and unknown codes; add current/legacy/damaged fixture tests.
- **Acceptance criteria:** Replies resolve by stable key when present; edits emit deterministic revisions; unknown codes retain type/timestamp/safe metadata; damaged text is traceable and inert.
- **Verification:** Run adapter unit tests for every supported schema and special case plus hostile-text serialization tests.
- **Out of scope:** PostgreSQL import, reactions/rich media, rendering, and search.
- **Blocked by:** EH-04-02, EH-04-04.
- **Priority:** High.
- **Model class:** Medium.

## EH-04-06 — Import one normalized text snapshot transactionally

- **Goal:** Persist identities, conversations, participants, text, replies, and revisions so partial work is never visible as a completed snapshot.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Adapter output is normalized; persistence owns PostgreSQL writes; batching is allowed but completion is atomic at snapshot visibility level.
- **Work to do:** Implement batched upserts and first/last-seen provenance; implement snapshot finalization and retry cleanup/reuse; wire the worker from validated SQLite through the selected adapter.
- **Acceptance criteria:** One valid fixture imports with correct relationships/provenance; failure before finalization is not visible as complete; retry reaches one logical result; adapter never writes PostgreSQL.
- **Verification:** Run PostgreSQL functional tests for success, mid-import failure, retry, and cross-archive isolation.
- **Out of scope:** Multi-snapshot permutation proof, media bytes, search indexes, UI, and production data.
- **Blocked by:** EH-04-03, EH-04-05.
- **Priority:** High.
- **Model class:** Medium.

## EH-04-07 — Prove idempotency and snapshot-order convergence

- **Goal:** Prove repeated and reordered text snapshots converge without inferred deletion or overwritten history.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Use synthetic A/B/C fixtures with overlap, omission, edits, row reordering, unknown types, and fallback identities.
- **Work to do:** Add repeated-import and all-permutation functional suites; define comparison rules excluding explicit snapshot chronology; document the private human-run Whapa aggregate comparison procedure.
- **Acceptance criteria:** Reimport changes no logical counts/keys; every A/B/C order yields equivalent preserved history; later omission leaves earlier records visible; revisions/provenance remain correct.
- **Verification:** Run every permutation twice on clean PostgreSQL databases and compare normalized snapshots; perform only sanitized aggregate oracle comparison when private data is available.
- **Out of scope:** Rich media, performance at real scale, production import, and fixing upstream source corruption.
- **Blocked by:** EH-04-06.
- **Priority:** High.
- **Model class:** Medium.
