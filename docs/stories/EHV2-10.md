# EHV2-10 stories — Production transport and release integrity

Owning feature: `docs/tasks/EHV2-10.md`. Private endpoints and release credentials never enter logs, Git, Plane, or client responses.

## EHV2-10-01 — Pin LiteLLM transport to validated addresses

- **Goal:** Prevent DNS rebinding between private-address validation and the transcription request.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Preserve original Host and TLS identity while connecting only to validated private addresses; redirects remain disabled.
- **Work to do:** Introduce a bounded transport that resolves once or pins the validated address through connection establishment.
- **Acceptance criteria:** Private validation followed by public DNS cannot receive media or credentials; mixed or public resolutions fail closed; TLS identity remains valid; timeout, size, and error classification is preserved.
- **Verification:** Fake resolver and transport rebinding tests plus sentinel scans.
- **Out of scope:** LiteLLM routing or private deployment.
- **Blocked by:** EHV2-06-03.
- **Priority:** Urgent.
- **Model class:** Complex — DNS, TLS identity, and secret media egress are one security boundary.

## EHV2-10-02 — Expose authenticated production MCP transport

- **Goal:** Make the established read-only MCP server callable through packaged production composition.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Reuse application reads and existing auth and audit envelopes; no Prisma access in delivery and no new tools.
- **Work to do:** Add bounded Streamable HTTP route and composition with secret-file credential handling; include it in the web image.
- **Acceptance criteria:** Unauthorized requests deny without tool or data disclosure; authenticated discovery exposes only established tools; archive and privacy policies apply; hostile content remains marked untrusted.
- **Verification:** Packaged HTTP transport tests for discovery, representative calls, auth negatives, limits, and restart.
- **Out of scope:** New MCP tools, public exposure, or Hermes deployment.
- **Blocked by:** EH-09-05.
- **Priority:** High.
- **Model class:** Complex — authenticated transport composition crosses the external trust boundary.

## EHV2-10-03 — Make Compose readiness fail closed

- **Goal:** Prevent an unusable or weakly hardened web container from being reported healthy.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** `/health` is liveness; `/ready` proves required runtime configuration, database, and migrations.
- **Work to do:** Supply explicit OIDC secret-file and configuration mappings, use readiness healthchecks, and apply image hardening defaults in Compose.
- **Acceptance criteria:** Missing OIDC, database, or migrations fails readiness; healthy composition passes; root filesystem and privilege defaults match container acceptance; no secrets enter Compose values.
- **Verification:** Compose rendering and lifecycle negatives, readiness probes, and container smoke.
- **Out of scope:** Private host deployment or Authentik blueprint changes.
- **Blocked by:** EH-10-05.
- **Priority:** High.
- **Model class:** Medium.

## EHV2-10-04 — Gate tagged releases on quality evidence

- **Goal:** Prevent publishing an image for a tagged SHA that has not passed required quality checks.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** The gate must verify the exact tag commit; no real image push is needed for tests.
- **Work to do:** Reuse or require the full CI workflow before the release push job and preserve supply-chain verification.
- **Acceptance criteria:** A failing gate prevents publication; all required checks refer to the tagged SHA; successful dry-run reaches the push boundary; immutable tag and image metadata is preserved.
- **Verification:** Workflow static tests and no-push success and failure simulations.
- **Out of scope:** Creating a release or changing registry credentials.
- **Blocked by:** EHV2-10-03.
- **Priority:** High.
- **Model class:** Simple.

## EHV2-10-05 — Require production integration seams in CI

- **Goal:** Make CI exercise the production boundaries that unit coverage excludes.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Keep fast unit coverage; add deterministic synthetic integration evidence without secrets or personal data.
- **Work to do:** Require functional PostgreSQL, entrypoint, Compose lifecycle, sidecar, container acceptance, viewer and MCP transport, and relevant coverage reporting.
- **Acceptance criteria:** Each production seam fails CI when broken; database adapter behavior is measured by functional tests; release consumes the same required result; runtime remains practical and deterministic.
- **Verification:** CI workflow validation and local aggregate dry run with documented durations.
- **Out of scope:** Private deployment or live third-party endpoints.
- **Blocked by:** EHV2-08-02, EHV2-08-04, EHV2-09-04, EHV2-10-01, EHV2-10-02, EHV2-10-04.
- **Priority:** High.
- **Model class:** Medium.
