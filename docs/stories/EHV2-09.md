# EHV2-09 stories — Privacy-safe unified reads

Owning feature: `docs/tasks/EHV2-09.md`. Every result and aggregate is archive-scoped and policy-filtered before delivery.

## EHV2-09-01 — Authorize grouping reads and commands

- **Goal:** Prevent grouping endpoints from revealing or mutating protected source chats without required authorization.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Direct IDs are non-enumerating; locked access requires a valid recent unlock grant; the most restrictive group policy applies.
- **Work to do:** Pass UI-purpose authorization into grouping reads and commands; filter candidates and validate every selected source.
- **Acceptance criteria:** Ordinary users cannot enumerate hidden or locked source metadata; locked grouping requires step-up; denied and missing IDs are indistinguishable; cross-archive and stale-version protections remain.
- **Verification:** Route and PostgreSQL policy matrix tests for normal, hidden, locked, missing, and cross-archive grouping.
- **Out of scope:** Privacy mutation UX or MCP policy.
- **Blocked by:** EHV2-02-01, EHV2-03-03.
- **Priority:** Urgent.
- **Model class:** Medium.

## EHV2-09-02 — List unified conversations once

- **Goal:** Make normal browsing show one complete conversation summary per active unified group.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Source conversations remain immutable; title, participant, and message summaries follow established unified precedence.
- **Work to do:** Query active unified groups and aggregate member-source summaries; update immediately after merge or unmerge.
- **Acceptance criteria:** A merged chat appears once; participant and last-message summaries include all member sources; unmerge restores separate rows; privacy and archive filters still apply.
- **Verification:** PostgreSQL list tests before merge, after merge, after unmerge, equal timestamps, and mixed policy.
- **Out of scope:** Merge UI or automatic grouping.
- **Blocked by:** EHV2-02-02.
- **Priority:** High.
- **Model class:** Medium.

## EHV2-09-03 — Scope source-account statistics fully

- **Goal:** Ensure every statistic respects the selected source account.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Logical messages count once; legacy rows need explicit documented fallback behavior.
- **Work to do:** Scope people, media, activity, and top-conversation aggregation through source provenance as messages already are.
- **Acceptance criteria:** No aggregate includes another account; merge or unmerge alone does not alter global totals; source totals remain stable and complete; privacy filters compose with source filters.
- **Verification:** PostgreSQL two-account merged and unmerged tests asserting every returned aggregate.
- **Out of scope:** UI charts or person merge.
- **Blocked by:** EHV2-02-04.
- **Priority:** High.
- **Model class:** Medium.

## EHV2-09-04 — Bind and stabilize every read cursor

- **Goal:** Prevent skipped, duplicated, or cross-context results across all paginated reads.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Cursor tuples must exactly match SQL ordering, including null handling and unique tie breakers.
- **Work to do:** Correct people and media tuple mismatches; bind cursors to read kind, direction, resource ID, filters, and UI mode; audit conversations, messages, timeline, and search.
- **Acceptance criteria:** Forward and backward pages cover tied, null, and multiply-linked rows exactly once; changed context rejects the cursor; archive and policy boundaries remain enforced; tokens stay bounded and signed.
- **Verification:** Unit token negatives and PostgreSQL permutation tests for every read kind.
- **Out of scope:** Offset pagination or new filtering features.
- **Blocked by:** EHV2-09-02, EHV2-09-03.
- **Priority:** High.
- **Model class:** Complex — cross-read cursor compatibility has broad behavioral blast radius.
