# EH-07 stories — Authenticated responsive archive viewer

Owning feature: docs/tasks/EH-07.md. Only the leaf stories below are executable assignments.

## EH-07-01 — Implement OIDC sessions and archive principal mapping

- **Goal:** Authenticate through an OIDC provider and map one admitted subject to one EchoHoard User/Archive.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Authentik is production, but functional tests use a fake provider; route and application-service boundaries both enforce archive scope.
- **Work to do:** Implement login/callback/logout/session validation; map configured issuer/subject claims to an archive principal; add anonymous, wrong-subject, invalid-session, and two-archive tests.
- **Acceptance criteria:** Valid configured subject receives only its archive principal; anonymous/invalid/wrong-subject requests are denied; secrets enter only through configuration/secret files; logout invalidates access.
- **Verification:** Run unit and fake-provider functional tests plus route-level negative authorization tests.
- **Out of scope:** Production Authentik configuration, admin/user onboarding, viewer screens, and MCP authentication.
- **Blocked by:** EH-01-06, EH-02-05.
- **Priority:** High.
- **Model class:** Medium.

## EH-07-02 — Build the responsive conversation-list shell

- **Goal:** Give an authenticated owner a responsive, accessible conversation list and empty/loading/error states.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Use ordinary Next.js components/routes and EH-06 services; do not query Prisma or load full conversations.
- **Work to do:** Build desktop/mobile-width navigation shell; connect bounded conversation pagination; add authenticated loading, empty, and failure states.
- **Acceptance criteria:** Conversation pages require a valid archive principal; pagination stays bounded; desktop/mobile layouts remain usable by keyboard; no source HTML is rendered.
- **Verification:** Run component/browser tests for auth denial, empty archive, multiple pages, keyboard navigation, and target widths.
- **Out of scope:** Message timeline, rich rendering, search, final branding, and production OIDC.
- **Blocked by:** EH-06-02, EH-07-01.
- **Priority:** High.
- **Model class:** Simple.

## EH-07-03 — Render a virtualized bidirectional message timeline

- **Goal:** Browse very large conversations around stable cursors without retaining the entire chat in browser memory.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Use EH-06 message-window service; stable message IDs anchor context; initial rendering may show safe text/unsupported placeholders only.
- **Work to do:** Implement bounded before/after loading and viewport virtualization; preserve scroll anchors; render direction, timestamp, replies, edits, and reactions safely.
- **Acceptance criteria:** A 150,000-message synthetic chat never loads all messages client-side; paging both directions has no duplicate/skip; stable context anchors survive adjacent inserts; hostile text remains escaped.
- **Verification:** Run browser pagination/anchor tests and record browser memory behavior on the synthetic large chat.
- **Out of scope:** Media playback, global search, accessibility audit, and visual polish.
- **Blocked by:** EH-07-02.
- **Priority:** High.
- **Model class:** Medium.

## EH-07-04 — Render rich messages and safe media states

- **Goal:** Present every required rich type, available media, and explicit missing/unsupported states in the timeline.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Use attachment IDs and EH-05 delivery policy; never construct source paths/URLs or render source HTML/SVG inline.
- **Work to do:** Add rich-type components/placeholders; integrate image, audio/video seek, and forced document download; add missing/unsafe/error states.
- **Acceptance criteria:** Common types render with correct relationships; safe media plays/downloads; missing/unknown content is explicit; active/spoofed content cannot execute inline.
- **Verification:** Run component/browser tests for every rich type, playback/seek, downloads, missing media, hostile metadata, HTML, SVG, and cross-archive denial.
- **Out of scope:** Search UI, transcoding, thumbnails, OCR, and final artwork.
- **Blocked by:** EH-05-06, EH-07-03.
- **Priority:** High.
- **Model class:** Medium.

## EH-07-05 — Add search/filter UI and stable context navigation

- **Goal:** Let the owner execute bounded search/filters and open a result at its stable conversation context.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Use EH-06 search contracts; preserve filter state in safe URL/application state; never expose raw SQL or unbounded counts.
- **Work to do:** Build global search/filter controls and result pagination; connect conversation/person/direction/date/media filters; navigate results to a message-context anchor.
- **Acceptance criteria:** All supported filters map deterministically to application queries; result pages are bounded; a result opens the correct stable context; special characters and empty/no-result cases are safe.
- **Verification:** Run browser tests for each filter, combinations, pagination, URL restoration, context navigation, hostile queries, and authorization denial.
- **Out of scope:** Semantic search, saved searches, AI summaries, and analytics.
- **Blocked by:** EH-06-04, EH-07-02.
- **Priority:** High.
- **Model class:** Medium.

## EH-07-06 — Verify accessibility, responsive behavior, and viewer performance

- **Goal:** Prove the complete viewer's critical paths meet the selected accessibility, responsiveness, and browser-memory expectations.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Fix only viewer integration defects; automated checks complement, not replace, keyboard/manual inspection.
- **Work to do:** Add critical-path automated accessibility checks; exercise desktop/mobile-width workflows; profile the large conversation and document accepted browser limits.

- **Verification:** Run the focused end-to-end suite, manual keyboard smoke, automated accessibility scan, and recorded 150,000-message profile.
- **Out of scope:** Production Authentik, final branding, native mobile app, export, and unrelated performance tuning.
- **Blocked by:** EH-07-03, EH-07-04, EH-07-05.
- **Priority:** High.
- **Model class:** Medium.
