# EH-02 stories — Archive schema and isolation

Owning feature: `docs/tasks/EH-02.md`. Only the leaf stories below are executable assignments.

## EH-02-01 — Add ownership, source, snapshot, and job schema

- **Goal:** Establish the archive ownership and ingestion lifecycle roots used by all later records.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** V1 has one real user, but ownership is explicit as User to Archive; source backups remain immutable; migrations target PostgreSQL.
- **Work to do:** Add a Prisma migration for User, Archive, Source, Snapshot, and ImportJob; include archive-scoped uniqueness, source hashes, provenance, and lifecycle fields; add synthetic migration tests.
- **Acceptance criteria:** Fresh and existing empty databases migrate cleanly; duplicate source identity is rejected within an archive without global uniqueness; jobs/snapshots cannot reference another archive's source.
- **Verification:** Run migrations and PostgreSQL positive/negative constraint tests against two synthetic archives.
- **Out of scope:** People, conversations, messages, attachments, application ports, and intake behavior.
- **Blocked by:** EH-01-06.
- **Priority:** High.
- **Model class:** Medium.

## EH-02-02 — Add people, identity, and conversation schema

- **Goal:** Model conservative identities and direct/group conversation membership within an archive.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Exact stable identifiers may link; fuzzy names never merge automatically; display names are observations rather than global identity.
- **Work to do:** Add Person, Identity, Conversation, and ConversationParticipant models/migration; enforce archive-scoped identifiers and participant references; add two-archive fixtures and constraint tests.
- **Acceptance criteria:** Exact identities can be associated with a person; similar names remain separate; cross-archive identity, conversation, or participant links are rejected.
- **Verification:** Apply the migration and run PostgreSQL tests for direct/group membership, identity uniqueness, and cross-archive denial.
- **Out of scope:** WhatsApp mapping, messages, revisions, attachments, fuzzy search, and UI.
- **Blocked by:** EH-02-01.
- **Priority:** High.
- **Model class:** Medium.

## EH-02-03 — Add message, revision, and reaction schema

- **Goal:** Store append-preserving messages, revisions, replies, reactions, stable source identity, and first/last-seen provenance.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** SQLite row IDs are not durable; later absence never deletes; unknown source types require safe metadata fields.
- **Work to do:** Add Message, MessageRevision, and Reaction models/migration; encode archive/conversation/sender/reply integrity and stable-key uniqueness; add provenance and unsupported-type fields.
- **Acceptance criteria:** Duplicate stable message/revision/reaction identities are rejected deterministically; revisions preserve first-seen snapshots; cross-archive and cross-conversation references fail.
- **Verification:** Apply the migration and run PostgreSQL constraint tests using two archives and repeated synthetic source identifiers.
- **Out of scope:** Identifier derivation algorithms, importer behavior, full-text search, and media.
- **Blocked by:** EH-02-01.
- **Priority:** High.
- **Model class:** Medium.

## EH-02-04 — Add attachment and message-link schema

- **Goal:** Model content-addressed attachments, availability state, hostile source metadata, and message relationships.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** EchoHoard owns media bytes; missing media is valid; Immich is not authoritative; paths/MIME are observations, not trusted access inputs.
- **Work to do:** Add Attachment and MessageAttachment models/migration; include SHA-256/CAS identity, availability, original metadata, size/dimension/duration fields, and archive-scoped links; add constraints.
- **Acceptance criteria:** Identical hashes can share one attachment within an archive while retaining multiple message links; missing records require no CAS path; cross-archive links are rejected.
- **Verification:** Apply the migration and run PostgreSQL tests for duplicate hashes, missing/available transitions, and isolation.
- **Out of scope:** Hashing bytes, path resolution, media serving, reconciliation, and Immich correlation.
- **Blocked by:** EH-02-01.
- **Priority:** High.
- **Model class:** Medium.

## EH-02-05 — Implement archive-scoped persistence ports

- **Goal:** Expose the completed schema through application-owned archive-scoped ports without leaking Prisma types.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Infrastructure implements application ports; every archive-owned lookup takes an explicit archive ID; use the synthetic two-archive fixture builder.
- **Work to do:** Define minimal application persistence ports for the modeled aggregates; implement Prisma adapters with explicit archive scope; add contract tests for positive and negative archive access.
- **Acceptance criteria:** No Prisma type crosses the infrastructure boundary; omitted archive scope is not representable in public port calls; tests prove no aggregate can be read through another archive.
- **Verification:** Run architecture checks, strict types, and PostgreSQL port contract tests for all modeled aggregate roots.
- **Out of scope:** Importer transactions, search queries, delivery routes, authentication, and statistics.
- **Blocked by:** EH-02-02, EH-02-03, EH-02-04.
- **Priority:** High.
- **Model class:** Medium.
