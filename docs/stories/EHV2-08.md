# EHV2-08 stories — Production ingestion integrity

Owning feature: `docs/tasks/EHV2-08.md`. Source backups remain immutable and no new broker or persistent service may be introduced.

## EHV2-08-01 — Complete the decrypt-to-import worker pipeline

- **Goal:** Make a production backup job adapt and import its decrypted database before completion.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Use the existing adapter/import ports and disposable work storage; unknown schemas fail visibly while preserving the source.
- **Work to do:** Compose fingerprinting/adaptation and transactional import after decryption; persist phase transitions; clean plaintext work only after success or classified failure.
- **Acceptance criteria:** Completed means normalized rows are durable; adaptation/import failure is retryable without partial visibility; unsupported schema preserves the snapshot; cleanup runs on every terminal path.
- **Verification:** PostgreSQL worker tests for success and failure at decrypt/adapt/import/finalize plus worker build.
- **Out of scope:** New queue infrastructure, live events, or schema guessing.
- **Blocked by:** EH-13-08.
- **Priority:** Urgent.
- **Model class:** Complex — production phase composition and transactional retry form one integrity boundary.

## EHV2-08-02 — Fence import leases through terminal state

- **Goal:** Prevent a stale worker from mutating or cleaning work owned by a replacement lease.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Keep PostgreSQL coordination and the existing single-worker topology; correctness must survive overlap during recovery.
- **Work to do:** Require the lease token on transitions/release/cleanup ownership; stop processing when renewal fails; make recovery/requeue atomic.
- **Acceptance criteria:** A stale runner cannot complete, fail, release, or clean replacement work; renewal failure aborts before another phase; normal retries remain idempotent.
- **Verification:** PostgreSQL two-runner expiry/takeover tests and focused state-machine tests.
- **Out of scope:** Distributed scheduler, broker, or parallel worker deployment.
- **Blocked by:** EHV2-08-01.
- **Priority:** High.
- **Model class:** Complex — lease fencing and cleanup ownership are concurrency-critical.

## EHV2-08-03 — Compose bounded production live intake

- **Goal:** Make the deployed sidecar path reach authenticated durable intake without unbounded buffering.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** The web role owns HTTP; keys come from secret files; requests are hostile and must be bounded before full buffering.
- **Work to do:** Compose account resolution and `LiveEventIntakeService`; align sidecar URLs with the real web route; stream-read with a hard byte limit.
- **Acceptance criteria:** A valid signed event reaches one durable receipt; unknown account/signature/oversize requests write nothing; chunked oversize requests are cancelled; worker normalization can consume the receipt.
- **Verification:** Route/unit tests and Compose-level signed webhook-to-normalized-message acceptance.
- **Out of scope:** Private deployment, pairing, or WhatsApp writes.
- **Blocked by:** EHV2-01-03, EHV2-01-04.
- **Priority:** Urgent.
- **Model class:** Medium.

## EHV2-08-04 — Prevent poison live receipts from starving the queue

- **Goal:** Let later valid receipts progress when an older receipt is permanently invalid.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Keep failures sanitized and source payload durable; use existing PostgreSQL fields and patterns rather than a new queue.
- **Work to do:** Claim pending receipts, track bounded attempts, classify retryable versus terminal failure, and release or recover stale claims.
- **Acceptance criteria:** Transient failures retry; permanent failures reach a visible terminal state; poison rows cannot occupy every batch forever; concurrent workers do not normalize one receipt twice.
- **Verification:** PostgreSQL poison/retry/concurrency/restart tests.
- **Out of scope:** Dead-letter service, operator UI, or payload deletion.
- **Blocked by:** EHV2-08-03.
- **Priority:** High.
- **Model class:** Medium.

## EHV2-08-05 — Converge live and backup edit revisions

- **Verification:** Adapter unit permutations and PostgreSQL live/backup edit convergence tests.
- **Out of scope:** New edit UI or revoke handling.
- **Blocked by:** EHV2-01-04.

## EHV2-08-06 — Invalidate expired sidecar pairing sessions

- **Goal:** Ensure expired or replaced QR codes cannot complete pairing upstream.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Expose only a fixed cancel/expire operation; QR material remains ephemeral and uncached.

- **Acceptance criteria:** Scanning an expired or replaced QR cannot enable capture; cancellation is idempotent; successful pairing still starts follow-sync once; no generic command surface appears.
- **Verification:** Controller and fake-sidecar race tests plus browser expiry/replay acceptance.
- **Out of scope:** Real account pairing or private deployment.
- **Blocked by:** EHV2-01-07.
- **Priority:** High.
- **Model class:** Medium.
