# EH-08 stories — Archive health and deterministic statistics

Owning feature: docs/tasks/EH-08.md. Only the leaf stories below are executable assignments.

## EH-08-01 — Define health states, freshness, and redaction

- **Goal:** Define deterministic archive-health classifications independently of delivery and UI.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Process liveness, snapshot freshness, import state, media coverage, unsupported data, and sanitized failures are distinct; default stale threshold is 36 hours.
- **Work to do:** Define health result types/classification rules; implement configurable freshness thresholds and diagnostic redaction; add boundary unit tests.
- **Acceptance criteria:** Healthy/warning/failed/empty/in-progress/stale classifications are deterministic; changing the threshold changes only freshness classification; messages, arbitrary paths, and secrets are absent.
- **Verification:** Run table-driven unit tests with sentinel secret/path/message values.
- **Out of scope:** PostgreSQL queries, endpoints, UI, notifications, and metrics exporters.
- **Blocked by:** EH-03-06.
- **Priority:** High.
- **Model class:** Simple.

## EH-08-02 — Implement archive-health read services and endpoints

- **Goal:** Produce archive-scoped health evidence for snapshots, latest message, jobs, counts, media, unsupported types, and sanitized failures.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Counts update only from successfully finalized snapshots; machine-readable endpoints remain private and bounded.
- **Work to do:** Add indexed health queries and application service; expose authenticated UI data and private readiness/health responses; add two-archive and import-state tests.
- **Acceptance criteria:** Required evidence fields reconcile to fixtures; finalized and failed/in-progress jobs are distinguished; cross-archive access fails; endpoints reveal no content, paths, or secrets.
- **Verification:** Run PostgreSQL functional and route tests for empty, active, failed, stale, unsupported, missing-media, and two-archive states.
- **Out of scope:** Statistics, UI cards, caching, public status, and notifications.
- **Blocked by:** EH-06-02, EH-08-01.
- **Priority:** High.
- **Model class:** Medium.

## EH-08-03 — Implement deterministic archive statistics

- **Goal:** Calculate totals, media by type/state, sent/received distribution, activity over time, and most-active conversations for one archive.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** PostgreSQL is the only store; definitions and time-bucket semantics must be documented; no AI-derived interpretation.
- **Work to do:** Define statistic result contracts/semantics; implement parameterized indexed queries; add fixture reconciliation and isolation tests.
- **Acceptance criteria:** Every required statistic matches direct fixture assertions; date/time-bucket behavior is deterministic; results remain archive-scoped and bounded.
- **Verification:** Run PostgreSQL tests over known distributions, empty archives, boundary dates, finalized/unfinalized imports, and two archives.
- **Out of scope:** UI, complex social analysis, notifications, and performance caching.
- **Blocked by:** EH-05-06, EH-06-04.
- **Priority:** High.
- **Model class:** Medium.

## EH-08-04 — Build authenticated health and statistics views

- **Goal:** Show trustworthy archive status and basic statistics without requiring log or database access.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Use EH-08 services through authenticated delivery; large counts and failures need accessible explicit states; no raw diagnostic content.

- **Out of scope:** New statistics, alerts, public status, production Authentik, and final artwork.
- **Blocked by:** EH-07-01, EH-08-02, EH-08-03.
- **Priority:** High.
- **Model class:** Medium.

## EH-08-05 — Measure and bound health/statistics performance

- **Goal:** Keep health and statistic responses within accepted latency at reference scale without adding another data store.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Choose indexes, safe cache, or incremental maintenance only from measurements; successful import is the publication boundary for counts.
- **Work to do:** Add representative benchmark cases to the existing corpus runner; capture query plans/latencies; implement the smallest measured optimization with invalidation/reconciliation tests.
- **Acceptance criteria:** Results record hardware/corpus/version/conditions; accepted response target is documented and met or a falsifiable blocker remains; counts never expose partial import or stale cross-archive data.
- **Verification:** Run benchmarks and EXPLAIN before/after, then functional tests across successful/failed/concurrent imports.
- **Out of scope:** Redis, metrics stack, real-data acceptance, and unrelated query tuning.
- **Blocked by:** EH-06-06, EH-08-04.
- **Priority:** High.
- **Model class:** Medium.
