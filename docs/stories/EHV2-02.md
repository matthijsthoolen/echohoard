# EHV2-02 stories — Reversible unified conversations

Owning feature: `docs/tasks/EHV2-02.md`. Source conversations and observations remain immutable evidence.

## EHV2-02-01 — Implement audited merge and unmerge commands

- **Goal:** Change presentation grouping through explicit reversible archive-scoped commands.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** EH-13 creates one-to-one unified groups. Merge accepts exact source-conversation IDs selected by the owner; it never infers from names.
- **Work to do:** Add merge/unmerge application commands, optimistic concurrency/versioning, audit metadata, and persistence; define title/avatar precedence as owner-managed presentation fields.
- **Acceptance criteria:** Merge and unmerge are idempotent; every source chat has exactly one active group; messages/observations are not rewritten; cross-archive, stale-version, and locked-policy bypass attempts fail.
- **Verification:** Domain/unit tests and PostgreSQL functional tests for merge, unmerge, replay, concurrency, and isolation.
- **Out of scope:** UI, fuzzy suggestions, person merge, or read aggregation.
- **Blocked by:** EH-13-08.
- **Priority:** High.
- **Model class:** Medium.

## EHV2-02-02 — Read one deterministic unified timeline

- **Goal:** Return a bounded timeline across all source chats in one unified conversation.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Stable cursor ordering must handle equal timestamps, missing timestamps, edits, and different owned accounts without offset pagination.
- **Work to do:** Extend read contracts/queries for unified groups; define deterministic message and revision order; include bounded source account/chat/import provenance suitable for UI display.
- **Acceptance criteria:** Pagination neither duplicates nor skips messages across account sources; ordering is stable across retries; unmerge immediately changes membership without changing message IDs; policy filtering remains applied by the service.
- **Verification:** PostgreSQL cursor/permutation tests plus generated large merged-chat benchmark.
- **Out of scope:** UI, search, statistics, MCP, or merge mutation.
- **Blocked by:** EHV2-02-01.
- **Priority:** High.
- **Model class:** Medium.

## EHV2-02-03 — Add merge, unmerge, and source-provenance UI

- **Goal:** Let the owner manage unified conversations and understand where each message came from.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Use existing design-system patterns. Destructive-looking unmerge requires a clear explanation that source data is retained.
- **Work to do:** Add source-chat selection and confirmation flow; merge/unmerge actions with conflict recovery; combined timeline indicators/details for receiving account, source chat, live/backup/import provenance without cluttering every message by default.
- **Acceptance criteria:** Owner can merge and reverse it; normal browsing shows one chat; provenance is keyboard/screen-reader accessible on demand; stale/conflict errors preserve the current grouping and explain recovery.
- **Verification:** Component tests and browser flows on mobile/desktop with two source chats and equal-timestamp messages.
- **Out of scope:** Automatic merge suggestions, person management, privacy controls, or source modification.
- **Blocked by:** EHV2-02-01, EHV2-02-02.
- **Priority:** High.
- **Model class:** Medium.

## EHV2-02-04 — Apply unified conversation semantics to search and statistics

- **Goal:** Make search filters, activity counts, and conversation summaries consistent with merged presentation.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Logical messages count once even when several observations support them. Source-level provenance remains available through explicit filters/details.
- **Work to do:** Update read/search/statistics contracts and queries; add unified/source account filters; document count/title/participant behavior across merge/unmerge.
- **Acceptance criteria:** Search by unified chat returns all member-source messages once; global counts do not change merely because chats merge; source-account filters remain accurate; pagination and performance targets are preserved.
- **Verification:** PostgreSQL functional tests and query-plan/benchmark checks before and after merge/unmerge.
- **Out of scope:** MCP mapping, UI controls, privacy policy, or identity/person merge.
- **Blocked by:** EHV2-02-02.
- **Priority:** Medium.
- **Model class:** Medium.

## EHV2-02-05 — Expose bounded unified chats through MCP

- **Goal:** Make existing read-only tools return unified presentation while retaining safe optional provenance.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** MCP has no merge mutation. Content remains untrusted and policy-filtered; account identifiers are minimized.
- **Work to do:** Map list/get/search/timeline results to unified IDs; add bounded source-count/provenance fields where safe; preserve stable tool names and cursor limits.
- **Acceptance criteria:** A merged chat appears once; messages appear once; unmerge changes future reads deterministically; no mutation or hidden raw identifier is exposed; existing hostile-content and archive-isolation tests pass.
- **Verification:** MCP contract/unit tests plus PostgreSQL-backed tool tests for merge/unmerge and source filters.
- **Out of scope:** Merge tools, live WhatsApp writes, privacy-policy implementation, or broad schema changes.
- **Blocked by:** EHV2-02-02, EHV2-02-04.
- **Priority:** Medium.
- **Model class:** Simple.
