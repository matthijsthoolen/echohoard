# EH-06 stories — Bounded reads and PostgreSQL search

Owning feature: docs/tasks/EH-06.md. Only the leaf stories below are executable assignments.

## EH-06-01 — Define bounded read and cursor contracts

- **Goal:** Define archive-scoped result, pagination, and cursor contracts shared by web and MCP delivery.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Every collection is bounded and cursor-paginated; cursors remain stable when older/newer archive data is added; delivery never receives Prisma types.
- **Work to do:** Define conversation/message-window/person/media/timeline query types; define opaque cursor encoding/validation and maximum bounds; add unit tests.
- **Acceptance criteria:** Unbounded requests are not representable; invalid/oversized cursors and limits fail deterministically; contracts carry archive scope and stable ordering fields.
- **Verification:** Run unit/property tests, strict types, and architecture checks.
- **Out of scope:** SQL, HTTP/MCP schemas, generated datasets, and UI.
- **Blocked by:** EH-04-07.
- **Priority:** High.
- **Model class:** Medium.

## EH-06-02 — Implement conversation, message-window, and person reads

- **Goal:** Provide archive-scoped application services for conversation lists, stable message context windows, and exact person resolution.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Use EH-06-01 contracts; application services call persistence ports; no delivery-layer queries or fuzzy identity merges.
- **Work to do:** Implement indexed persistence queries and service orchestration; support before/after message windows; add archive isolation and concurrent-import visibility tests.
- **Acceptance criteria:** Results are bounded/deterministically ordered; cursors remain usable after adjacent data arrives; cross-archive reads return no information; queries avoid per-row N+1 behavior.
- **Verification:** Run PostgreSQL functional tests for pagination directions, boundaries, concurrent finalized/unfinalized imports, and two archives.
- **Out of scope:** Full-text/trigram search, media bytes, HTTP, UI, and MCP.
- **Blocked by:** EH-06-01.
- **Priority:** High.
- **Model class:** Medium.

## EH-06-03 — Add migration-managed full-text search

- **Goal:** Search message text with PostgreSQL full-text indexes through an archive-scoped application service.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Use Prisma migrations plus parameterized SQL for search structures/hot queries; no Elasticsearch, vectors, or embeddings.
- **Work to do:** Add search-vector/GIN migration; implement bounded text query and stable ordering; add special-character, empty, ranking, and isolation tests.
- **Acceptance criteria:** Search returns only the requested archive within configured bounds; special/empty queries are deterministic and injection-safe; query plans use the intended GIN structure at representative size.
- **Verification:** Apply migrations and run PostgreSQL search tests plus recorded EXPLAIN checks.
- **Out of scope:** Trigram/fuzzy filters, UI, MCP mapping, and performance tuning beyond index proof.
- **Blocked by:** EH-06-01.
- **Priority:** High.
- **Model class:** Medium.

## EH-06-04 — Add trigram and filtered search with stable cursors

- **Goal:** Add conversation/person, direction, date-range, media-type, and fuzzy-name/text filtering to the bounded search service.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Use pg_trgm only where specified; all SQL is parameterized; ordering/cursors remain deterministic under archive growth.
- **Work to do:** Add migration-managed trigram indexes; implement filter composition and cursor fields; document exact search/filter semantics.
- **Acceptance criteria:** Every filter combination is archive-scoped and bounded; fuzzy matching never merges identities; cursor pagination has no duplicate/skip in tested inserts; intended indexes serve representative filters.
- **Verification:** Run PostgreSQL combinatorial filter/cursor tests, injection cases, and EXPLAIN assertions.
- **Out of scope:** Search UI, semantic similarity, AI summaries, and corpus generation.
- **Blocked by:** EH-06-02, EH-06-03.
- **Priority:** High.
- **Model class:** Medium.

## EH-06-05 — Generate the deterministic reference corpus

- **Goal:** Produce a repeatable synthetic dataset of five million messages and one million attachment records without personal content.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Generation must be seedable, bounded-memory, and compatible with real migrations; performance runs may be CI-optional.
- **Work to do:** Implement seeded corpus generation/loading; include conversation size/date/media distributions and two archives; document hardware/run metadata capture.
- **Acceptance criteria:** The requested counts load reproducibly; rerunning with the same seed yields equivalent logical distributions; no fixture contains real identity/message/media data.
- **Verification:** Generate a small CI corpus and the full local reference corpus; compare counts, distribution checksums, and memory behavior.
- **Out of scope:** Query tuning, production data, benchmarks, and UI.
- **Blocked by:** EH-06-01.
- **Priority:** High.
- **Model class:** Simple.

## EH-06-06 — Benchmark and tune bounded reads/search

- **Goal:** Demonstrate p95 two-second warm search and first-page conversation loads on recorded production-class hardware.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Tune only measured bottlenecks; use existing PostgreSQL/index boundaries; record conditions with every number.
- **Work to do:** Define representative query set and repeatable runner; capture latency/resource/query plans on the reference corpus; add only measured index/query adjustments with regression checks.
- **Acceptance criteria:** Accepted runs record hardware, versions, corpus seed/counts, cold/warm conditions, percentiles, and EXPLAIN summaries; target queries meet p95 two seconds or leave a falsifiable documented blocker.
- **Verification:** Run the versioned benchmark repeatedly and compare plans/timings before and after each accepted adjustment.
- **Out of scope:** Real-data acceptance, hardware changes, caching services, vectors, and UI performance.
- **Blocked by:** EH-06-04, EH-06-05.
- **Priority:** High.
- **Model class:** Medium.
