# EHV2-01 stories — Invisible multi-account live ingestion

Owning feature: `docs/tasks/EHV2-01.md`. `wacli` is untrusted upstream infrastructure behind an EchoHoard-owned adapter. Never expose a generic command runner or its SQLite schema to application services.

## EHV2-01-01 — Pin and verify the wacli integration contract

- **Goal:** Record the exact supported upstream artifact and smallest safe integration surface.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** The planning baseline is MIT-licensed `openclaw/wacli` v0.15.0, but implementation must re-check current stable release, signatures/checksums, maintenance, `whatsmeow` compatibility, JSON/NDJSON/webhook schemas, QR behavior, and remote side effects.
- **Work to do:** Add an ADR/upstream pin with license/hash/version; define allowlisted auth, follow-sync, health, and signed-message-event contracts; enumerate forbidden commands and schema-coupling; decide the tested upgrade/rollback process without changing product semantics.
- **Acceptance criteria:** One immutable artifact is reproducible and licensed; contract fixtures cover history/live/revoke/media/account/connection events; send/edit/delete/react/read-state/group/presence-management and generic commands are unreachable; upstream replacement requires only the adapter contract.
- **Verification:** Verify artifact checksum/signature and license; run recorded fixture/schema compatibility checks; static-test the command allowlist and forbidden surface.
- **Out of scope:** Sidecar image, deployment, pairing UI, event persistence, or live account use.
- **Blocked by:** EH-13-08.
- **Priority:** High.
- **Model class:** Reasoning — upstream behavior and side effects must be proven before the fixed adapter is implemented.

## EHV2-01-02 — Package an isolated fixed-command wacli sidecar

- **Goal:** Run one pinned sidecar per owned account with protected storage and no general CLI reachability.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Session stores contain linked-device keys. Runtime commands are fixed entrypoints only; no shell, user-supplied argv, public port, or direct store mount into web/MCP.
- **Work to do:** Add reproducible image/service contracts for pairing and follow-sync roles; enforce non-root ownership, isolated named-account stores, bounded resources, secret-file webhook key, restart/health behavior, and immutable upstream pin.
- **Acceptance criteria:** Account A cannot read/write account B's store; normal sync exposes only signed bounded events and health; forbidden flags/commands fail static contracts; image contains no credentials and runs without package downloads.
- **Verification:** Container/build tests, Compose rendering checks, filesystem-mode/isolation tests, command-contract negatives, and secret sentinel scan.
- **Out of scope:** Private deployment, application event ingestion, admin UI, or real pairing.
- **Blocked by:** EHV2-01-01.
- **Priority:** High.
- **Model class:** Medium.

## EHV2-01-03 — Accept signed live events into a durable inbox

- **Goal:** Receive, authenticate, deduplicate, and durably stage bounded sidecar events before acknowledging them.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Webhook delivery may retry, reorder, disconnect, or overflow. Source content is hostile; acknowledgement means durable receipt, not successful normalization.
- **Work to do:** Implement HMAC verification with replay bounds, account routing, payload size/type validation, stable event receipt IDs, durable inbox rows, and sanitized rejection/status metrics through application/infrastructure ports.
- **Acceptance criteria:** Invalid/missing/stale signatures and unknown accounts fail without writes; replay creates one receipt; accepted response occurs only after durable commit; content/identifiers are absent from logs and metrics; backpressure is explicit rather than silent loss.
- **Verification:** Unit vectors plus PostgreSQL functional tests for replay, out-of-order events, tampering, size limits, restart, and concurrent receivers.
- **Out of scope:** WhatsApp normalization, sidecar control, media download, or UI.
- **Blocked by:** EHV2-01-01, EH-13-08.
- **Priority:** High.
- **Model class:** Medium.

## EHV2-01-04 — Normalize live and history messages into observations

- **Goal:** Convert accepted sidecar message/history events into the same account-scoped observation model used by backups.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Preserve raw type identifiers only as bounded metadata; no `wacli` table names cross the adapter. Stable WhatsApp chat/message IDs and account scope drive identity.
- **Work to do:** Add versioned event adapter fixtures; map conversations, participants, messages, replies, reactions/edits where supported, media references, and unsupported events; finalize receipts transactionally with observations/materialization.
- **Acceptance criteria:** Live/history replay is idempotent; same IDs on different accounts do not collide; unknown types remain explicit; failed adaptation remains retryable with no partial completion; output matches backup adapter identity contract.
- **Verification:** Adapter unit fixtures and PostgreSQL functional tests for two accounts, history/live duplicates, reordered events, and unsupported/corrupt payloads.
- **Out of scope:** Delete/revoke handling, backup supersession, sidecar deployment, or UI.
- **Blocked by:** EHV2-01-03.
- **Priority:** High.
- **Model class:** Medium.

## EHV2-01-05 — Preserve live revoke and deletion events

- **Goal:** Apply later WhatsApp revoke/delete observations without erasing content EchoHoard already captured.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Use EH-13 tombstone semantics. Some events arrive before their message or only after a reconnect/history replay.
- **Work to do:** Map revoked/deleted-for-me event shapes; attach ordered observations; update source-deleted presentation state; preserve prior content/media and allow a later original observation to fill an empty tombstone.
- **Acceptance criteria:** Captured content remains retrievable with an explicit deleted marker; delete-before-original stays a tombstone then fills safely; replay/out-of-order delivery converges; deletion never triggers owner soft delete or CAS removal.
- **Verification:** Unit event permutations and PostgreSQL functional tests for before/after/replay/account-isolation cases.
- **Out of scope:** Owner deletion, WhatsApp delete commands, UI styling, or purge.
- **Blocked by:** EHV2-01-04, EH-13-07.
- **Priority:** High.
- **Model class:** Medium.

## EHV2-01-06 — Reconcile live-only observations with nightly backups

- **Goal:** Remove the temporary live-only status when an authoritative backup confirms the same message while retaining both provenance records.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Backup absence never deletes. Match only ADR-approved account/chat/message identities or collision-safe deterministic fallbacks.
- **Work to do:** Add reconciliation state/logic for live-only, backup-confirmed, and unresolved-collision cases; merge compatible observation-derived metadata deterministically; expose safe counts/health.
- **Acceptance criteria:** Live then backup and backup then replay both yield one logical message; the backup observation replaces no live evidence; unconfirmed deleted messages remain preserved/live-only; ambiguous fallback identities never auto-collapse.
- **Verification:** PostgreSQL permutation tests with overlap, deletion, edits, media, collision cases, and repeated nightly imports.
- **Out of scope:** Import exclusion UI, manual conversation merge, or live deployment.
- **Blocked by:** EHV2-01-04, EHV2-01-05.
- **Priority:** High.
- **Model class:** Medium.

## EHV2-01-07 — Add owned-account pairing and health settings

- **Goal:** Let an administrator pair, enable, pause, re-pair, and inspect an account without seeing `wacli` as a separate product.
- **Repository:** `/home/matthijs/projects/echohoard`
- **Context / constraints:** Pairing is owner-attended and admin-only. QR/session material is ephemeral, never logged/cached by shared proxies, and does not enter the database beyond safe status; controls invoke fixed application operations only.
- **Work to do:** Add account settings/read models; implement a bounded pairing-session controller around the fixed sidecar role; render QR/status/last durable event/reconnect/backup-confirmation health; add pause/re-pair confirmations and recovery guidance.
- **Acceptance criteria:** Anonymous/non-admin/cross-archive requests deny; QR expires and cannot be replayed; no general command/argv/store access is exposed; normal users see only EchoHoard UI; health separates connection, receipt, normalization, and backup confirmation.
- **Verification:** Unit controller tests, browser admin/expiry/denial flows, response cache-header checks, and fake-sidecar acceptance.
- **Out of scope:** Private deployment, account deletion, WhatsApp write features, or direct DB browsing.
- **Blocked by:** EHV2-01-02, EHV2-01-03.
- **Priority:** High.
- **Model class:** Complex — safe interactive QR lifecycle across web and fixed sidecar is the one irreducible integration boundary.

## EHV2-01-08 — Deploy and accept two-account live capture

- **Goal:** Prove the pinned sidecar and EchoHoard adapter operate privately without duplicate or silently lost acknowledged events.
- **Repository:** `/home/matthijs/projects/unraided-treasures`
- **Context / constraints:** Use approved Vault/Komodo deployment paths. Pairing is attended. Start with a disposable/test path where available; record only sanitized counters/timestamps/digests.
- **Work to do:** Add private stack/Vault/storage/network/backup configuration; deploy fixed roles; pair configured accounts; exercise reconnect, live message, revoke, restart, nightly backup reconciliation, and denied command/network boundaries.
- **Acceptance criteria:** Two account stores and credentials are isolated; live messages appear once; acknowledged events survive restart; revoke is preserved; later backup confirms without duplication; no forbidden command/port/store access exists; recovery/re-pairing runbook is tested.
- **Verification:** Approved deployment/status/log/probe procedures plus attended UI/live-to-backup checks and isolated secret/path denials.
- **Out of scope:** Sending messages, guaranteed full history, bulk production media backfill, or V2 initiative sign-off.
- **Blocked by:** EHV2-01-06, EHV2-01-07.
- **Priority:** High.
- **Model class:** Complex — attended linked-device and private deployment acceptance cannot be reduced to repository tests.
