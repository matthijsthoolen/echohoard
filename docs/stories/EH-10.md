# EH-10 stories — Production web and worker packaging

Owning feature: docs/tasks/EH-10.md. Only the leaf stories below are executable assignments.

## EH-10-01 — Build one pinned image with separate web/worker roles

- **Goal:** Produce one multi-stage image that starts the web or worker composition root from the same immutable artifact.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Node/runtime/application dependencies are pinned; wa-crypt-tools exists only for the worker role; no deployment-specific values are embedded.
- **Work to do:** Add the multi-stage build and role entry command; install/verify the pinned Python decryption dependency; add build and role-start smoke tests.
- **Acceptance criteria:** One image digest starts both roles; web starts without the worker running; worker can load the decrypt adapter; build context/history contains no secrets or private data.
- **Verification:** Build the image, inspect layers/history, and run both role smoke tests with synthetic configuration.
- **Out of scope:** Non-root filesystem hardening, Compose, SBOM, private deployment, and real decryption keys.
- **Blocked by:** EH-07-06, EH-08-05, EH-09-05.
- **Priority:** Medium.
- **Model class:** Medium.

## EH-10-02 — Harden runtime user, writable paths, and secret mounts

- **Goal:** Run both roles non-root with only documented writable data/work paths and read-only secret files.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Web and worker receive only role-required filesystem access; secrets are files, not image layers or committed environment values.
- **Work to do:** Configure non-root UID/GID and ownership; make root filesystem/read-only paths explicit; add sentinel secret-file and forbidden-write container tests.
- **Acceptance criteria:** Both roles run non-root; writes outside approved paths fail; secret files remain read-only and absent from logs/image history; web lacks worker-only write/key access.
- **Verification:** Run container identity/mount/write tests and scan layers/logs/process listings for sentinel secrets.
- **Out of scope:** Vault provisioning, Unraid paths, database privileges, health commands, and Compose.
- **Blocked by:** EH-10-01.
- **Priority:** Medium.
- **Model class:** Simple.

## EH-10-03 — Add lifecycle, migration, and generic Compose contracts

- **Goal:** Provide generic external-PostgreSQL Compose plus safe health, readiness, migration, and shutdown behavior for both roles.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** Generic placeholders only; worker interruption must leave a recoverable lease/job; web remains available when worker stops.
- **Work to do:** Add role health/readiness and graceful shutdown; document/implement migration command; add generic Compose with external PostgreSQL and placeholder secret files.
- **Acceptance criteria:** Compose validates and starts against a fresh PostgreSQL database; readiness reflects migrations/dependencies; stopping/killing worker does not corrupt a job; web remains available.
- **Verification:** Render/start generic Compose, migrate, stop/kill each role during representative phases, and verify recovery/readiness.
- **Out of scope:** Private Unraid/Authentik/Vault/Caddy/Komodo values, SBOM, and real data.
- **Blocked by:** EH-10-01, EH-10-02.
- **Priority:** Medium.
- **Model class:** Medium.

## EH-10-04 — Record SBOM, licenses, reproducibility, and rollback

- **Goal:** Make redistributed dependencies and image provenance reviewable and upgrades/rollback repeatable.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** wa-crypt-tools licensing/distribution obligations must be recorded; the repository license remains an explicit maintainer decision before outside contributions.
- **Work to do:** Generate an SBOM/attribution artifact; pin and checksum upstream artifacts; document reproducible-build expectations, dependency upgrades, and digest rollback.
- **Acceptance criteria:** SBOM names Node/Python/application dependencies and licenses; upstream pins/checksums are verifiable; documentation identifies the open project-license decision without silently choosing it.
- **Verification:** Generate/inspect the SBOM, verify checksums, build twice under documented conditions, and run a rollback dry run using known digests.
- **Out of scope:** Legal advice, private registry, deployment mutation, vulnerability remediation, and release automation.
- **Blocked by:** EH-10-01.
- **Priority:** Medium.
- **Model class:** Simple.

## EH-10-05 — Run container-level synthetic acceptance and recovery

- **Goal:** Prove the packaged artifact can migrate, import synthetic data, browse/search it, serve media, and answer all MCP tools across worker interruption.
- **Repository:** /home/matthijs/projects/echohoard
- **Context / constraints:** This integrates completed application behavior only; use generic Compose and synthetic fixtures; fixes stay within established contracts.
- **Work to do:** Add a container acceptance harness for the critical path; exercise worker kills/recovery during intake phases; capture sanitized artifact/digest/test evidence.
- **Acceptance criteria:** Fresh containers complete the synthetic critical path; every MCP tool responds; safe media works; worker recovery converges without duplicates; no secrets/private paths enter evidence.
- **Verification:** Run the harness twice from clean volumes, including the documented kill points, and compare final IDs/counts/hashes.
- **Out of scope:** Private infrastructure, Authentik live login, real backups, Borg restore, and Hermes.
- **Blocked by:** EH-10-03, EH-10-04.
- **Priority:** Medium.
- **Model class:** Medium.
