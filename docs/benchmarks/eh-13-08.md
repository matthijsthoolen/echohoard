# EH-13-08 bounded rematerialization benchmark

The versioned runner is `pnpm benchmark:rematerialization`. It generates one
synthetic archive with one account, a backup/live-shaped/backup import sequence,
and a bounded message slice (default 250; maximum 10,000). It measures one
exclusion and re-enable, then replays the same request to prove the resulting
input-set digest is stable and idempotent.

```sh
DATABASE_URL=postgresql://... pnpm benchmark:rematerialization -- --messages 1000
```

The JSON report is written to
`docs/benchmarks/eh-13-08-rematerialization-latest.json` by default. It records
only synthetic counts, timings, and booleans; generated IDs and message bodies
are not published. The bound is intentionally suitable for attended EH-12
planning, not a claim about real-archive throughput. Run it against a fresh
PostgreSQL schema after `prisma migrate deploy`, and remove the benchmark
archive afterward (the runner does this in a `finally` block).
