# EH-06-06 bounded read/search benchmark

The versioned runner is `pnpm benchmark:reads`. It executes the application
read services against PostgreSQL, not a mocked or in-memory adapter, and writes
non-personal JSON evidence to `docs/benchmarks/eh-06-06-latest.json` (override
with `--output`). The default run expects the CI corpus; use `--full` for the
five-million-message / one-million-attachment reference scale.

```text
DATABASE_URL=postgresql://... pnpm generate:corpus -- --full --output /tmp/reference-corpus.jsonl
DATABASE_URL=postgresql://... pnpm benchmark:reads -- --full --iterations 31 --cold-iterations 5
```

Corpus generation is intentionally separate from loading: the loader/import
path owns transactional visibility and must load the generated JSONL into a
disposable PostgreSQL database before this runner is started. The runner
selects the largest archive internally and never records its identifier or
source content.

The query set is fixed and bounded: the first conversation page (50 rows), a
common full-text search, the same search in a representative date window, and
a fuzzy body search. Every case records five cold-session samples and 31 warm
samples by default. “Cold” means a new Prisma session; PostgreSQL and OS page
caches are not flushed, so this is not misreported as a cold-disk benchmark.
Warm p95 is the acceptance metric. The JSON also records CPU/RAM/storage and
container limits, Node/PostgreSQL versions, the generator seed/counts/checksum,
and concise `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)` node/index summaries.
